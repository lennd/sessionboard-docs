These tools are served by the Sessionboard MCP server. To connect an assistant, see [Marketing API authentication](/sessionboard-marketing/api/authentication#ai-assistants).

## How an event is doing, and sign-ups

Turnout and pacing for an event or webinar, for organizations whose plan includes Sessionboard Marketing. These tools need the `read:marketing` / `write:marketing` scopes, which are in preview: tick them under **Opt-in** when you create an API token, or name them in your OAuth `scope` request. Like the rest of Marketing, they read the whole organization, so a token restricted to particular events cannot use them.

| Tool | Hints | Description |
|------|-------|-------------|
| `get_turnout` | read | How an event is doing (default: the next upcoming one). Returns registrations so far; an estimate of registrations and turnout at the event date, with a range, a confidence label and a sentence on how it was estimated; pace against the goal; the last comparable event; registrations by day before the event; the time of week your emails get opened most; and two or three suggestions. With too little history it returns no estimate and says so |
| `set_turnout_goal` | write · destructive | Set or clear the event's registration and attendance goal. With no goal set, the last comparable event's numbers are used |
| `get_ai_discovery` | read | Found by AI for one event: whether the AI assistants Sessionboard asks each week name the event, a speaker or a session, against the check before; the answers; one next move; and `business_hub`, what ChatGPT itself reports for your claimed business profile (mentions, clicks and discovery topics over 28 days, with topics you have no session on). Answer as "ChatGPT reports 42 mentions and 9 clicks in the 28 days to Nov 6" |
| `update_ai_discovery` | write · destructive | Change the questions an event's check asks or turn the weekly check off, or record your ChatGPT Business Hub numbers (`business_hub`: mentions, clicks, topics, the last day of the 28 days, the claimed domain). Business Hub has no API: the assistant records only numbers you give it |
| `add_signup_form` | write | Add an email sign-up to an event page draft with nothing to fill in (the words come from the event; people confirm their email before they join). Publishing the page stays yours. Calling it again returns the same form |
| `gate_recording` | write | Ask for an email before a recording or clip plays. Anyone with a valid email watches; only people who tick the box join your list |
| `count_signups` | read | How many people signed up in the last days (default 7), by status and by where they signed up |
| `list_subscribers` | read | Who signed up, newest first: status, where, which list; filters by status, source, list, event, name or email, date |

Every predicted number is an estimate, and the assistant is told to say so. Cancelled registrations are not counted. When your own history is too thin, the estimate can draw on aggregate statistics across Sessionboard organizations, never on another organization's events or numbers.

Try: *"How's the Austin field lab doing?"* or *"Will we hit 300 registrations for the spring webinar?"* or *"Make the goal for the summit 600 registrations and 450 attending."*

## A tour's listing page

A tour is a multi-stop series of in-person events. Its listing page is one public page that lists every stop, and each stop appears there once its own event page is live. A custom domain serves one page, so to put a whole tour on your own domain (for example events.example.com), put the domain on the listing page, not on a stop's page. These tools use the same preview scopes and the same organization-wide rule as above.

| Tool | Hints | Description |
|------|-------|-------------|
| `get_tour_listing` | read | The listing pages a tour can go on, each with `site_id`, `url`, `has_tour` (it already lists this tour), `live`, `published` and `has_unpublished_changes` |
| `add_tour_to_listing` | write · idempotent | Make the tour's listing page, or add the tour to an existing listing page (`siteId`). Calling it again returns the same page, never a second one. Nothing is published and nobody is emailed. Pass the returned `site_id` to `connect_custom_domain` |

Try: *"Make a listing page for the Event Content Lab tour and put it on events.example.com."*

## Podcasts, newsletter, journeys, video, website, consent and sponsor links

The same scopes and the same organization-wide rule apply. Tools that publish, send, switch on emails to real people or share data with a sponsor never run straight from an assistant: Sessionboard answers `needs_approval` with a link, and a person approves the request in Sessionboard Marketing (**Waiting for your OK**). The assistant is told to pass the link on and not to call again. Drafts are made at once, and nothing in a draft reaches anyone until a person publishes or sends it.

| Tool | Hints | Description |
|------|-------|-------------|
| `list_podcasts` | read | The organization's shows: title, event or series, episode counts by status (draft, approved, published), the feed URL and the public page |
| `get_podcast` | read | One show with its episodes: title, status, source session, whether the audio is ready, duration |
| `get_podcast_stats` | read | Downloads in the last 7 days and in total, by episode, for one show or all. A download counts once per listener per episode in any 24 hours; bots are not counted |
| `make_podcast_from_event` | write | Turn an event into a podcast: the event's show (made on the first call, reused after) with a draft episode for every session that has a recording or an approved audio recap. Nothing is published |
| `add_podcast_episodes` | write | Add draft episodes from sessions or from recordings in Media. Sessions already in the show are skipped |
| `set_podcast_episode_status` | write · destructive | Move episodes to draft, approved or published. Publishing puts them on the public feed, so an assistant's request waits for a person's OK |
| `get_newsletter` | read | The newsletter: name, from name, reply-to, list, cadence (after each event, monthly or manual), sending state and its issues with their status |
| `draft_newsletter_issue` | write | A draft issue written from an event's recaps, clips, quotes and podcast episodes, or an empty one. Sends nothing |
| `get_newsletter_issue` | read | One issue: subject, preheader, blocks, status, scheduled time and how many people it would reach |
| `schedule_newsletter_issue` | write · destructive | Send an issue to everyone subscribed to the list, now or at a set time. Waits for a person's OK |
| `get_newsletter_results` | read | A sent issue's results: delivered, opens, clicks by link, unsubscribes, bounces |
| `list_journeys` | read | The four journeys (no-show → recording, attendee → recap and next event, new subscriber → welcome, invited but not registered → reminder): on or off, delay, the email and how many people each would reach |
| `update_journey` | write · destructive | Change a journey's delay or email, or switch it on or off. Switching on starts emails to real people, so an assistant's request waits for a person's OK |
| `get_video_playback` | read | A recording's playback details: the stream or file, poster, captions and chapters |
| `get_watch_report` | read | Who watched a recording and how far (percent and minutes), newest first; can keep only people who watched at least a given share |
| `gate_video` | write | Ask for an email to watch a recording, before it plays or after a set time (for example five minutes in). Any valid email unlocks it; only people who tick the box join your list. Returns the page to share |
| `get_video_options` | read | A recording's gate, button and end card, and what viewers see today (by default "Register for" your next event at the end, then a "Watch next" card) |
| `set_video_options` | write · destructive | Change the button (your next event, your own label and link, or none; at the end or from a set time) or turn off the end card. Changes what visitors see, so the assistant asks you first |
| `schedule_premiere` | write | Play a recording at a set time for everyone on the event page, with questions and polls beside it and a Remind me button; on demand afterwards. It goes on the page draft; publishing stays yours. Calling it again moves the time |
| `list_premieres` | read | Premieres with their state (upcoming, live, ended, cancelled), reminders asked for and questions |
| `update_premiere` | write · destructive | Move, cancel or end a premiere, or stop taking questions. The assistant asks you first |
| `get_premiere_room` | read | A premiere's questions (visible, answered, hidden) and each poll's votes |
| `manage_premiere_poll` | write · destructive | Add a poll (it opens at once), or open, close or delete one. The assistant asks you first |
| `moderate_premiere_question` | write · destructive | Hide a question, show it again, or mark it answered. The assistant asks you first |
| `get_website_tag` | read | The tag for your own website: the snippet to paste, whether it has been seen and when, page views and visitors in the last days, top pages |
| `who_visited` | read | People you already know who viewed pages on your site: name, company, account, views, last page. Narrow by a word in the page address, by days (up to 90) or to target accounts |
| `get_person_consent` | read | A person's lists (newsletter, partners and others) with their status, and their consent history newest first, one sentence per entry |
| `list_sponsor_shares` | read | Private sponsor links: sponsor, audience, created, expires, active, views and downloads |
| `share_with_sponsor` | write · destructive | A private link for a sponsor to the people who opted in to hear from partners, and only them. Waits for a person's OK |
| `revoke_sponsor_share` | write · destructive | Stop a sponsor link working at once. Views and downloads so far stay listed |

Try: *"Turn the summit into a podcast"*, *"Draft this month's newsletter from the summit"*, *"Who watched the keynote?"* or *"Who from our target accounts looked at the pricing page this week?"*
