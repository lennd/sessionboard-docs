LiveBuzz (LiveControl) is the campaign and registration system behind many Clarion and other large-format events. Connect Sessionboard to LiveBuzz once, map each Sessionboard event to a LiveBuzz campaign, and Sessionboard pushes accepted sessions, rooms, and speakers. Turn on **Enable Continuous Sync** if you want Sessionboard to keep them updated about every 30 minutes.

The API key and organization are saved on the connection. Each Sessionboard event maps to one LiveBuzz campaign.

<Tip>
Before you start, have your LiveBuzz API key, organization (the subdomain in the LiveControl address, such as `livebuzz` or `clarion`), and campaign ID (the slug after `/campaign/` in that address, such as `api-sandbox-2026`). Accept the sessions you want in LiveBuzz and assign rooms first. Every person you want pushed needs a first name, last name, and email.
</Tip>

## Connect LiveBuzz

LiveBuzz is set up at the **organization**. Open it from **Settings > Integrations** or from **Apps**. Event **Settings > Integrations** no longer lists LiveBuzz.

<Note>
**Sessionboard adds LiveBuzz to your organization for you.** Email [support@sessionboard.com](mailto:support@sessionboard.com) to request it. The LiveBuzz card stays locked until then, and the steps below assume it is already available. Everything after that — the connection, the event mapping, and the field mapping — you do yourself.
</Note>

<Steps>
  <Step title="Open LiveBuzz">
    Go to organization **Settings > Integrations** and click **Settings** on LiveBuzz, or open **Apps** and click **LiveBuzz**.
  </Step>
  <Step title="Save the connection">
    On the **Connections** tab, enter a **Name**, the **LiveBuzz API Key**, the **LiveBuzz Organization** (the subdomain, such as `clarion` for `clarion.control.buzz`), and the **LiveBuzz Domain** (`control.buzz` unless you are on UAT). Click **Save connection**.
  </Step>
  <Step title="Map a Sessionboard event">
    Click **Map events** on the connection. Choose the Sessionboard event and enter the **LiveBuzz Campaign ID** — the slug in the LiveControl URL, such as `api-sandbox-2026` from `livebuzz.control.buzz/campaign/api-sandbox-2026`. Already mapped events are hidden. Click **Save mapping**.
  </Step>
  <Step title="Choose what to push">
    Open **Event Settings** for that mapping. Turn on **Enable Continuous Sync** if you want Sessionboard to push this event to LiveBuzz about every 30 minutes. Leave it off to sync only when you click **Sync**. Continuous sync still requires at least one accepted session that has not ended.

    Leave **Push sessions (seminars)** and **Push speakers (customers)** on unless you only want rooms. Leave **Remove from LiveBuzz when un-accepted** on unless you want un-accepted sessions to stay in LiveBuzz.

    Uncheck session roles that should not sync — for example chairs or co-authors. Leave every role checked to push everyone on accepted sessions.

    Optional: paste a **LiveBuzz Badge Type ID** if the campaign should stamp that badge on customers Sessionboard creates. Click **Save event settings**.
  </Step>
  <Step title="Map fields">
    Use **Map Speaker Fields**, **Map Session Fields**, and **Map Room Fields** to choose which Sessionboard fields write to LiveBuzz for that mapping. First name, last name, and email are required for speakers. Title, start, and end are required for sessions. Room name is required for rooms. You cannot save until those are mapped.
  </Step>
</Steps>

<Note>
Credentials are encrypted and are not shown again after you save. Leave a secret blank when you edit a connection to keep the current value.
</Note>

## What syncs

Only **accepted** sessions and the people on those sessions sync. Which session roles sync is an event-mapping setting — by default every role on the event (speaker, moderator, chairperson, and custom roles). Uncheck a role on **Event Settings** if those people should stay out of LiveBuzz. Rooms come from the event's session rooms.

If the event has **speaker acceptance** on, a speaker is not pushed until they have accepted. Other roles are not gated by acceptance.

A person needs a first name, last name, and email. Anyone missing those is skipped and is not removed from LiveBuzz.

| Sessionboard | LiveBuzz |
| --- | --- |
| Session room | Theater |
| Accepted session | Seminar (title, description, start, end, room) |
| Person on an accepted session | Customer (name, email, company, job title, biography, headshot) |
| Person assigned to a session | Registration on that seminar, with their role |

When a session is no longer accepted, Sessionboard cancels that speaker's LiveBuzz registration unless you turned **Remove from LiveBuzz when un-accepted** off. The seminar is cancelled rather than deleted, so LiveBuzz keeps its history.

<Note>
The **customer record always stays** in LiveBuzz, even when the person has no registrations left. LiveBuzz has no way for Sessionboard to remove a customer, so someone removed from every session remains on the campaign. Delete them in LiveBuzz if you need them gone.
</Note>

On **Map Speaker Fields**, pick where LiveBuzz writes back. For **LiveBuzz Registration ID** and **LiveBuzz Badge ID**, choose an event-only text contact field, or click **Create** to add one. Organization fields are not listed. Those fill in when LiveBuzz returns them — a field stays empty if the campaign does not return that value. Add the fields to the contact layout if you want them visible on the record.

## Field mappings

**Map Speaker Fields**, **Map Session Fields**, and **Map Room Fields** apply only to the event mapping you have selected. Defaults cover name, email, company, biography, headshot, title, description, times, and room.

LiveBuzz needs a first name, last name, and email to create a customer, a title, start, and end to create a seminar, and a room name to create a theater. Those rows stay on the mapping and cannot be removed. Badge type and the LiveBuzz `source` stamp come from **Event Settings**, not from these maps.

## Run a sync

If **Enable Continuous Sync** is on for that mapping, Sessionboard runs a full sync about every 30 minutes while the event has at least one accepted session that has not ended. When the checkbox is off, click **Sync** when you need an update.

To push immediately, click **Sync** on **Map Events**, or use **Sync to LiveBuzz** from Agenda, Sessions, All Contacts, Speakers, Chairpersons, or Moderators. **Check drift** on the connection compares Sessionboard to LiveBuzz without writing.

**Sync** on **Map Events**, or **Sync to LiveBuzz** from Agenda Options with nothing selected, is a full sync — the same accepted set as a scheduled run, including removals when **Remove from LiveBuzz when un-accepted** is on. If you select rows and click **Sync to LiveBuzz**, only those records update. Sessionboard will not cancel the rest of the campaign.

## Stop a sync that is taking too long

A full sync of a large event can run for a while, because LiveBuzz limits how fast Sessionboard may send records.

To stop one, open the event and go to **History > Integrations > Sync History**, then click **Cancel** on the row that is still **In Progress**. Confirm, and the sync stops after the record it is currently sending — usually within a few seconds.

Cancelling does not undo anything:

- Everything already sent stays in LiveBuzz.
- The records it had not reached yet are listed in that sync's results as skipped.
- Running the sync again continues from where it stopped instead of creating the same records twice.

The row shows **Warning** once it stops, with the reason in the results.

## Add or remove a mapping

<Warning>
Once a mapping has synced, you cannot change its **campaign ID**, and you cannot change the connection's **organization** or **domain**. Sessionboard blocks the save, because the records it already created in LiveBuzz are only reachable under those values — changing them would leave every one of them behind and start creating duplicates.

To move an event to a different campaign, delete the mapping and add a new one. To move to a different LiveBuzz organization or domain, add a new connection. Fix a typo before the first sync, when there is nothing to leave behind.
</Warning>

Use **Add event mapping** to point another Sessionboard event at another campaign on the same connection. You can also add a second connection if you have a different LiveBuzz organization or key.

To remove a mapping, use the trash control on that row. Previously synced LiveBuzz records stay in LiveBuzz; Sessionboard stops updating them.

## "The service rejected these credentials"

Saving the event mapping is the first time Sessionboard calls LiveBuzz. Saving the connection does not check the key, because the campaign is not known yet — so a key that appeared to save fine can still fail here.

LiveBuzz answers several different problems the same way, so read the rest of the message. It quotes what LiveBuzz said and the address Sessionboard called.

- **The address is wrong.** Compare the host in the message against your LiveControl URL. `clarion.control.buzz` and `livebuzz.control.buzz` are different organizations, and `control.dev.uat.buzz` is UAT — a UAT key does not work against production.
- **The campaign is wrong.** The campaign ID is the slug after `/campaign/` in the LiveControl URL, such as `api-sandbox-2026`. A campaign the API key's user cannot open is rejected the same way a bad key is.
- **LiveBuzz does not recognize the address Sessionboard calls from.** If the message mentions an IP address that is not permitted, LiveBuzz restricts that API user to a list of addresses. Email [support@sessionboard.com](mailto:support@sessionboard.com) — this one is between Sessionboard and LiveBuzz, and you cannot fix it from Sessionboard.
- **The key belongs to a different account.** A key that works on one connection is still rejected if the organization, domain, or campaign on this one points somewhere the key has no access.

## Still having issues?

Email [support@sessionboard.com](mailto:support@sessionboard.com) and include the connection name, the LiveBuzz organization and campaign ID, and the session or contact that did not sync. Do not send the API key.
