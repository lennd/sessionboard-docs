## Event details

**Settings → Event Details** holds the basic information every other part of the event reads from.

![The Event Details page in Event Settings — name, slug, type, website, location, timezone, dates and theme, with the Custom fields and Exhibitors & Sponsors sections below](/images/kb/event-details.png)

| Field | Example |
| --- | --- |
| **Event Name** | ACME Conference 2025 |
| **Event Slug** | `app.sessionboard.com/acme-conference-2025` |
| **Event Type** | Conference |
| **Event Website URL** | https://www.sessionboard.com/ |
| **Event Location** | San Francisco, CA |
| **Timezone** | (GMT-5:00) America/New_York |
| **Starts / Ends At** | 12/02/2025 8:00am → 12/05/2025 5:00pm |
| **Theme** | A short description of your event's focus and audience |
| **Logo image** | 300 × 300 |
| **Background image** | 1500 × 500 (use an image with no words) |

Below the details, **Custom fields** lists any event-level fields your organization has created (from **Organization Settings > Library > Fields**, on the **Event** tab — they appear on every event), and **Exhibitors & Sponsors** chooses which group types this event manages.

<Tip>Sessionboard's AI features use **Event Type**, **Website URL**, **Location**, and **Theme** to understand the nature, audience, and goals of your event. Fill them in so [Agents](/agents/overview) give better results.</Tip>

### Timezone

**Timezone** is the clock the rest of the event reads from, including everything participants see. Session times and custom **Date & Time** fields in a portal are rendered in this zone and labelled with its abbreviation, rather than in the reader's own timezone — see [dates and times in the portal](/portals/portals-101#dates-and-times-in-the-portal). Leave it blank and those times fall back to UTC with nothing naming the zone.

## Record settings

**Settings → Record Settings → General** controls how submissions, contacts, and uploads behave across the event.

![The General tab of Record Settings — submission limits, subsession limits, math, and portal and contact settings](/images/kb/record-settings-general.png)

### Submission and subsession limits

**Set submission limit** caps how many sessions one user can submit, counted across every form in the event rather than per form.

**Limit subsessions per session** caps how many subsessions can hang off a parent session, up to 500. It's enforced both in the admin and on Call for Papers forms. Set one default for the event, then add **filtered overrides** to give a different limit to sessions matching a filter — for example, a higher cap on anything with Format = Expo. Leave the default blank for no limit.

### Math

**Enable math in submission rich text fields** adds MathJax support to WYSIWYG fields on session submissions — LaTeX, MathML, and ASCIIMath — in the admin, portals, and Call for Papers. It applies to session submissions only, and the math tools load only when the setting is on, so leave it off unless your submitters need notation.

<Tip>This one matters for medical, scientific, and academic programs, where abstracts routinely contain formulas that break in a plain text field.</Tip>

### Portal and contact settings

- **Automatically provision contact portal access** — contacts get portal access when added or imported.
- **Collect additional contacts** — gather additional contacts (an assistant or a co-author's coordinator, for example) for speakers via the submission form. See [additional contacts](/contacts/additional-contacts).

- **Enable primary speakers** — designate specific speakers or authors as "Primary" across sessions, so it's clear who the point of contact is and who to feature for a given session or abstract. Submission forms can cap how many participants are marked primary — see [primary speaker limits](/sessions/submission-forms#participant-information).
- **Enable Participant Acceptance** — let participants accept or decline each role they hold on a submission, with optional withdrawal and custom portal status wording. See [participant acceptance](/speakers/speaker-acceptance).

### Speaker headshot limitations

Controls what the photo editor will accept. When on, accepted formats, dimension limits, and the optional file-size cap apply everywhere a headshot can be uploaded — submission forms, portal forms, application forms, and Edit Profile — for both admins and portal users.

The line submitters see *under* the field is separate. On a submission form it comes from the question: your **Help Text** if you wrote any, otherwise a type-and-size hint such as “Images only (up to 5 GB)”. Set **Maximum file size** in **Customize Question** to change the advertised size, or leave it blank for 5 GB. [Session Files](/sessions/enable-upload-download-content) and these headshot size limits do not change that hint. See [Session submission forms](/sessions/submission-forms).

![Speaker Headshot Limitations switched on — accepted file formats, the Limit File Size switch, and width and height fields](/images/kb/record-settings-headshots.png)

- **Accepted file formats** — All Image Types, PNG, JPEG, or GIF. At least one must stay selected.
- **Limit file size** — an optional cap between 10 KB and 5 GB. Files over the cap are rejected in the photo editor, and the uploader is told why.
- **Limit dimensions** — a max width and/or height in pixels. Larger uploads are automatically downsized to fit before storage rather than rejected. Setting both also makes the crop tool enforce that aspect ratio. Leave blank for no limit.

<Note>Dimensions and file size behave differently: an oversized *image* is resized for you, while an oversized *file* is refused. If you want to guarantee consistent headshots, set the dimensions.</Note>

### Sponsor & exhibitor logo limitations

The same controls for sponsor and exhibitor logos: accepted formats, an optional file size cap, and max width and height. Larger logos are automatically downsized to fit, and setting both dimensions makes the crop tool enforce the matching aspect ratio.

![Sponsor & Exhibitor Logo Limitations — the same format, file size and dimension controls as headshots](/images/kb/record-settings-logos.png)

Like headshots, this is enforced in the logo editor everywhere a sponsor or exhibitor logo can be uploaded. On a submission form, the line under the field still follows that question’s **Help Text** and **Maximum file size**, not this cap.

### Date & time

**Time Format** sets whether times use a 12-hour clock (with AM/PM) or a 24-hour clock everywhere in this event — dashboards, grids and detail panels, not just exports. **Advocacy card date & time** is separate: it chooses how session dates appear on [Advocacy](/marketing/advocacy) share cards, US style (*Monday, Oct. 26, 4:00 – 6:00 PM*) or EU style (*Monday, 26 Oct, 16:00 – 18:00*).

### Exports

**Export date format** sets the date and time format used in CSV and spreadsheet downloads for this event. Leave it on **Organization default** to follow the format set for your organization under **Org Settings > Details**, where **System default (YYYY-MM-DD HH:mm)** applies unless you choose another. Both pickers can be set back to their default after you have saved a specific format. Turn on **Include Day/Date/Time split columns** to add separate Day, Date, and Time columns alongside each datetime column, which saves reformatting when the export feeds a schedule or a print agenda.

### Record IDs

Prefixes must be 3–6 uppercase characters, and they're used when generating IDs for submissions, contacts, and groups such as sponsors and exhibitors.

![The Date & Time and Record IDs sections — time format, export date options, and the Submission, Contact and Group prefixes](/images/kb/record-settings-record-ids.png)

**Keep original ID with subsessions** makes a subsession keep its own ID instead of nesting under the parent — `SESS-23` rather than `SESS-601-1`.

<Warning>The prefix is applied when an ID is displayed, not when the record is created, so changing it renames **every** existing record too — `SESS-23` becomes `ABST-23` everywhere at once. Only the number is stored per record. Avoid changing prefixes once you've sent IDs to reviewers or speakers.</Warning>
