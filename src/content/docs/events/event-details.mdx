Once you've created an event, configure its details before onboarding contacts. Navigate to the **Settings** module within your event.

## Event details

**Settings → Event Details** holds the basic information every other part of the event reads from.

![The Event Details page in Event Settings, with fields for name, slug, type, website, location, timezone, dates, and theme](/images/kb/6712855b-image-png-Jul-08-2026-07-58-41-4907-PM.png)

| Field | Example |
| --- | --- |
| **Event Name** | ACME Conference 2025 |
| **Event Slug** | `app.sessionboard.com/acme-conference-2025` |
| **Event Type** | Conference |
| **Event Website URL** | https://www.sessionboard.com/ |
| **Event Location** | San Francisco, CA |
| **Timezone** | (GMT-5:00) America/New_York |
| **Starts / Ends At** | 12/02/2025 8:00am → 12/05/2025 5:00pm |
| **Theme** | A short description of your event's focus and audience |
| **Logo image** | 300 × 300 |
| **Background image** | 1500 × 500 (use an image with no words) |

<Tip>Sessionboard's AI features use **Event Type**, **Website URL**, **Location**, and **Theme** to understand the nature, audience, and goals of your event. Fill them in for better [AI Evaluations](/evaluations/ai-evaluations).</Tip>

## Record settings

**Settings → Record Settings → General** controls how submissions, contacts, and uploads behave across the event.

![The General tab of Record Settings, showing submission limits, subsession limits, math, and portal and contact settings](/images/kb/44999870-image-png-Jul-08-2026-08-00-11-4553-PM.png)

### Submission and subsession limits

**Set submission limit** caps how many sessions one user can submit, counted across every form in the event rather than per form.

**Limit subsessions per session** caps how many subsessions can hang off a parent session, up to 200. It's enforced both in the admin and on Call for Papers forms. Set one default for the event, then add **filtered overrides** to give a different limit to sessions matching a filter — for example, a higher cap on anything with Format = Expo. Leave the default blank for no limit.

### Math

**Enable math in submission rich text fields** adds MathJax support to WYSIWYG fields on session submissions — LaTeX, MathML, and ASCIIMath — in the admin, portals, and Call for Papers. It applies to session submissions only, and the math tools load only when the setting is on, so leave it off unless your submitters need notation.

<Tip>This one matters for medical, scientific, and academic programs, where abstracts routinely contain formulas that break in a plain text field.</Tip>

### Portal and contact settings

- **Automatically provision contact portal access** — contacts get portal access when added or imported.
- **Collect additional contacts** — gather additional contacts for speakers via the submission form.

![A submission form showing the additional contacts section that this setting turns on](/images/kb/9668a480-image-png-Jul-08-2026-08-01-22-7102-PM.png)

- **Enable primary speakers** — designate specific speakers or authors as "Primary" across sessions, so it's clear who the point of contact is and who to feature for a given session or abstract.
- **Enable Participant Acceptance** — let participants accept or decline each role they hold on a submission, with optional withdrawal and custom portal status wording. See [participant acceptance](/speakers/speaker-acceptance).

### Speaker headshot limitations

Controls what headshots your event will accept. When on, the rules apply everywhere a headshot can be uploaded — submission forms, portal forms, application forms, and Edit Profile — for both admins and portal users. There's no per-form override.

![Speaker Headshot Limitations expanded, with accepted file formats, a file size toggle, and width and height fields](/images/kb/7c239ac8-image-png-Jul-08-2026-08-03-08-7478-PM.png)

- **Accepted file formats** — All Image Types, PNG, JPEG, or GIF. At least one must stay selected.
- **Limit file size** — an optional cap between 10 KB and 5 GB. Files over the cap are rejected, and the uploader is told why.
- **Limit dimensions** — a max width and/or height in pixels. Larger uploads are automatically downsized to fit before storage rather than rejected. Setting both also makes the crop tool enforce that aspect ratio. Leave blank for no limit.

<Note>Dimensions and file size behave differently: an oversized *image* is resized for you, while an oversized *file* is refused. If you want to guarantee consistent headshots, set the dimensions.</Note>

### Sponsor & exhibitor logo limitations

The same controls for sponsor and exhibitor logos: accepted formats, an optional file size cap, and max width and height. Larger logos are automatically downsized to fit, and setting both dimensions makes the crop tool enforce the matching aspect ratio.

![Sponsor and Exhibitor Logo Limitations, with the same format, file size, and dimension controls as headshots](/images/kb/fbc08e9d-image-png-Jul-08-2026-08-09-53-9560-PM.png)

Like headshots, this is set event-wide and applies everywhere a sponsor or exhibitor logo can be uploaded.

### Exports

**Export date format** sets the date and time format used in CSV and spreadsheet downloads, defaulting to `YYYY-MM-DD HH:mm`. Turn on **Include Day/Date/Time split columns** to add separate Day, Date, and Time columns alongside each datetime column, which saves reformatting when the export feeds a schedule or a print agenda.

### Record IDs

Prefixes must be 3–6 uppercase characters, and they're used when generating IDs for submissions, contacts, and groups such as sponsors and exhibitors.

![The Record IDs section with Submission, Contact, and Group prefix fields and the keep original ID checkbox](/images/kb/32485221-image-png-Jul-08-2026-08-14-02-5061-PM.png)

**Keep original ID with subsessions** makes a subsession keep its own ID instead of nesting under the parent — `SESS-23` rather than `SESS-601-1`.

<Warning>The prefix is applied when an ID is displayed, not when the record is created, so changing it renames **every** existing record too — `SESS-23` becomes `ABST-23` everywhere at once. Only the number is stored per record. Avoid changing prefixes once you've sent IDs to reviewers or speakers.</Warning>
