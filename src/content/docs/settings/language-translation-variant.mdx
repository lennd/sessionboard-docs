<Note>
Language variants are part of the **Language Variants & Translations** feature, which Sessionboard turns on per event. Contact [support@sessionboard.com](mailto:support@sessionboard.com) or your Customer Success Manager to have it enabled. Once it is on, a **Supported Languages** section appears on **Settings → Event Details**.
</Note>

<Tip>
Looking to show your **portal** in another language? That is a separate switch — see [multi-language portals](#multi-language-portals) below. Language variants store the translations; a multi-language portal is what lets participants pick a language and read them.
</Tip>

## What are language variants?

A language variant is a second copy of a field for another language: a translated **field name** (so "AV Notes" can read "AV-Hinweise" to a German speaker) and, on each record, a translated **value**. The default language stays English (United States) — admins keep collecting and managing data in it — and variants sit beside it.

Variants are available on text, text area, rich text and dropdown fields, standard or custom, for **sessions**, **contacts** and **groups** (sponsors and exhibitors). For dropdown-style standard fields such as Track, Format, Level and Language, the option labels themselves can be translated.

## Which languages are supported?

An event can add any of thirty-one additional languages: English (United Kingdom), French, French (Canada), German, Spanish, Portuguese, Portuguese (Brazil), Dutch, Italian, Polish, Turkish, Swedish, Danish, Finnish, Norwegian Bokmål, Russian, Chinese, Chinese (Simplified), Chinese (Traditional), Japanese, Korean, Thai, Vietnamese, Indonesian, Malay, Hindi, Arabic, Arabic (Saudi Arabia), Arabic (United Arab Emirates), Arabic (Egypt) and Hebrew. The default language is always English (United States) and cannot be changed.

## Important considerations

- **Labels and values, not the interface.** Variants translate field names and the values stored in them. Sessionboard's own buttons, menus and system text stay in English for admins.
- **Embeds:** Website embeds can display your language variants. When an embed is set to (or requested in) a language you have enabled, translated session titles, descriptions and field values appear automatically, and untranslated fields fall back to the default language. See [Embeds](/sessions/embeds).
- **Integrations:** Not every integration syncs language variants. If you rely on one, ask support@sessionboard.com to confirm before you translate at scale.
  - Translated fields are available through Sessionboard's open API. For Track, Format, Level and Language, the API returns the translated option label when the field's variant is enabled and that option has a translation; otherwise it returns the default label.
- **Forms:** On the older forms interface, variant fields are admin-only and cannot be placed on portal, submission, intake or application forms. The v2 form builder can place an enabled variant on the form beside its default-language field — see [multi-language submissions](/sessions/submission-forms#multi-language-submissions).

## Turn on languages for the event

1. Open **Settings → Event Details** and scroll to **Supported Languages**. **Default Language** shows English (United States) and is locked.
2. Under **Language Variants**, click **Add Language** and pick a language from the **Select Languages** list. It is added as a chip; repeat for each language you need.
3. Click **Save** at the bottom of the page.

![Supported Languages on Event Details — Default Language locked to English (United States), Language Variants with an Add Language button and a German chip](/images/kb/languages-supported.png)

![The Select Languages dialog listing the languages that can be added, with their locale codes](/images/kb/languages-select-dialog.png)

To drop a language later, click the **×** on its chip and save. Any translations already entered for that language stop showing.

## Enable a variant on a field

Adding a language does not translate anything by itself. Turn the variant on field by field:

1. Open **Settings → Library → Fields** (or the organization's Fields library for a global field) and pick the tab for the record type — **Contact**, **Group** or **Submission**.
2. Find the field, open its **⋯** menu and choose **Edit**.
3. Expand **Language variants**. Each enabled language has a box for the translated field name — type it, then tick **Show this variant**.
4. Click **Save Changes**.

![Edit Session Field with the Language variants section expanded — German with the translated name AV-Hinweise and Show this variant ticked](/images/kb/field-language-variants.png)

<Note>
**Show this variant** is what makes the translation active. A translated name without the box ticked is stored but never shown — on records, in embeds, in the API or on forms.
</Note>

## Enter translated values on a record

Once a field has an active variant, every record of that type shows a small globe beside the field:

1. Open the record — a session, contact, sponsor or exhibitor — in its sidebar or profile page.
2. Click the globe icon next to the field. The tooltip reads *Edit language variants for "&lt;field>"*.

   ![A session's Custom Fields with a globe icon beside AV Notes](/images/kb/session-translation-globe.png)

3. In **Edit Language Variants**, the default-language value is shown read-only at the top; type the translation in the box for each language and click **Done**.

   ![The Edit Language Variants panel — the default AV Notes value locked, a German (de) box with a translation typed in, Done and Cancel](/images/kb/session-translation-sidebar.png)

4. **Done** queues the change — the globe shows *Changes pending* — and it is written when you save the record.

To fill one language from another without editing each record, add the **Update language value** action to an [automation](/automations/overview#update-language-value). It translates or copies a field into an enabled language whenever the record changes. For sessions that already exist, fill them all at once instead.

## Fill a language for many sessions at once

Use this to translate every English description into French before a portal opens, or to give German-only submissions a real English title. A German-only submission arrives with its German text copied into the English Title and Description (see [below](#which-language-a-submission-came-in)). To replace that with a translation, translate Title (German) into Title (English) and choose **Replace existing values**.

1. On the Sessions list or the Submissions view, select the sessions. To take every session on the page, tick the checkbox in the header.
2. In the bulk actions bar, open **More** and choose **Update language values**.
3. Set **Copy from** to a field and its language, and **Write to** to the field and language it goes into. The two can be the same field in different languages, such as Title (German) into Title (English), or two different text fields.
4. Under **How**, pick **Translate** to translate the text, or **Copy as-is** to move it over unchanged.
5. Under **If the target already has a value**, pick **Only fill empty values** to leave anything already written alone, or **Replace existing values** to overwrite it.
6. Click **Continue**, check the summary, then click **Update N sessions**.

The update runs in the background, up to 5,000 sessions at a time, and the dialog shows how many are done. When it finishes you see how many sessions were updated, and how many were skipped because the source was empty, the target already had a value, or the session no longer exists. You can close the dialog while it runs; a message appears when the update finishes.

- **Which fields.** Title, Description, and custom text fields (single-line, paragraph, and rich text). Rich-text formatting such as bold and lists is kept when translating. Copying rich text into a plain text field keeps the words and drops the formatting.
- **Which languages.** The event's default language and any language turned on for the event. If no extra language is on, **Update language values** is greyed out, and its info icon says why.
- **Automations.** These updates do not trigger field-change [automations](/automations/overview#when), so filling 2,000 titles does not start 2,000 automation runs.
- **Edits made during the update.** With **Only fill empty values**, each session is checked again just before it is written. A value someone types in while the update is running is kept.

## Which language a submission came in

Every session submitted through a form records the language the submitter used. With [multi-language submissions](/sessions/submission-forms#multi-language-submissions) on, that is the language they picked on the form; otherwise it is the event's default language. Sessions submitted before September 2026 have it filled in where Sessionboard can tell from the saved translations, and left blank where it can't.

- **On the session.** The session sidebar shows **Submitted via &lt;form> · &lt;language>** under the session title.
- **In the Public API.** Add `submission_source` to `expand` on the session search or get endpoint (`?expand=submission_source`, or `"expand": ["submission_source"]` in a search body). Each session then carries `submission_source: { form_id, form_name, language }`. `language` is a locale code such as `de-DE`, or `null` when it is unknown. `submission_source` is `null` for sessions that were not submitted through a form.

This matters when the only text a submitter entered was in a translated field. Sessionboard copies it into the default-language Title and Description so the session is never untitled, and `submission_source.language` tells an integration that the text is really German, say.

## Multi-language portals

Language variants cover admin-facing field labels. A multi-language portal covers the other side: what participants read.

Turn on **Enable multi-language portal** in **Portals → [portal] → Configuration**, under **Multi-language**. A language picker appears in the portal toolbar. Profile, submission, and form fields that have language variants are captured in the selected language, and anything without a saved translation can be auto-translated.

Choose what gets auto-translated:

- Page headers, titles and descriptions
- Field labels without a saved translation
- Placeholders and dropdown values
- Confirmation and success messages

Which languages are available is set under **Settings → Event Details → Supported Languages** (see [Turn on languages for the event](#turn-on-languages-for-the-event)).

<Tip>
Saved language variants always win over auto-translation. Where the exact wording matters — a legal consent line, an award category name — add a variant and leave auto-translate to handle the rest.
</Tip>

Where a variant is the same language as your default — English (United Kingdom) alongside English (United States), say — auto-translate leaves the text alone and shows exactly what you authored. Putting text through machine translation into its own language rewrites wording that was already right: an abbreviation such as `Dr` came back expanded to `Doctor`, which is why dropdown values could read differently in the variant than in the form you built.

Custom [portal participation section titles](/portals/portals-101#participation-sections) are auto-translated along with the other portal header copy.
