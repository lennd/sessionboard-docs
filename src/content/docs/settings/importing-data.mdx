Every module with a table — Contacts, Sessions, Sponsors, Exhibitors and Event Team — takes a CSV or Excel file through **Options → Import**. The same import, run on a file you exported first, updates records that already exist. This article covers the file rules, the three-step importer and the update flow.

## Before you build the file

- **Save as UTF-8.** Excel does this by default in North America; elsewhere use **File → Save As → CSV (Comma delimited)** and set **Tools → Web Options → Encoding** to UTF-8. Google Sheets' **Download → CSV** is already UTF-8.
- **1,000 rows per file.** Split larger lists.
- **Keep the column headers in English.** Sessionboard matches your columns to its fields by their English labels, even when your admin language is German, Spanish or French. The template's notes row is in your language; the header row is not, on purpose.
- **Phone numbers** need the country code: `+1 (303) 555-0142`.
- **URLs** (website, LinkedIn, headshot) start with `https://`.
- **Multi-select values** are separated by a pipe: `Cardiology | Pediatrics`.
- **Session dates and times** are `YYYY-MM-DD HH:mm` (`2027-04-12 09:30`). Date-only fields on Award and Interest form submission imports are `YYYY-MM-DD`. If Excel keeps reformatting a date column, select it, press Ctrl + 1, choose **Text** and re-enter the values.
- **Currency fields** take an amount in the field's currency (`1500.00` or `SAR 1500`); a negative amount fails the row with an error naming the column.
- **Formula fields** are calculated, so import their source fields instead (Fee and Paid, not Balance). Formatting, Calculation and Assignment [Field Rules](/settings/field-rules) run on the imported values.
- **File fields** take a hosted `https://` URL per file, pipe-separated when the field allows several (up to 10 per cell, 50 MB each); Sessionboard downloads them after the row lands. Blank file cells leave existing files alone. Headshots use the **Headshot URL** column.

### Custom fields first

The template only contains fields that are on the module — so [create any custom fields](/faq/how-to-create-and-delete-custom-fields) you want to fill before you generate it, and add them to the module view's **Columns** so they are included.

## Get the template

<Steps>
  <Step title="Open the importer">
    In the module you are importing into, click **Options → Import**. On **Event Team** the **⋯** menu beside **Add** has the same **Import** entry.

    ![The Options menu on All Contacts — Import, Export .CSV, Export .XLSX](/images/kb/contacts-options-menu.png)
  </Step>
  <Step title="Generate Template">
    Click **Generate Template**. A CSV downloads with one column for every field in your current view plus a notes row that states each column's format. Fill it in — or match your own file's headers to it — and delete the notes row before uploading.

    ![The Import Contacts panel with Upload File and Generate Template](/images/kb/contacts-import.png)
  </Step>
</Steps>

<Note>
The Sessions template includes a **Session Friendly ID** column. Leave it empty for new sessions — Sessionboard assigns the ID when the session is created. It is only filled in when you [import to update](#import-to-update-existing-records).
</Note>

## Import new records

<Steps>
  <Step title="Upload File">
    Click **Options → Import → Upload File**, then drop your CSV or Excel file on the importer (or click to browse). The importer states the row limit and what the module accepts.
  </Step>
  <Step title="Select Header Row">
    Confirm which row holds your column names — normally row 1 — or tick **No headers in the sheet**. Change the encoding here if accented characters look wrong. Click **Next**.

    ![Select Header Row, with row 1 chosen as the header and the three data rows below it](/images/kb/contacts-import-header-row.png)
  </Step>
  <Step title="Map Columns">
    Every Sessionboard field is listed under **Template Fields**; required ones carry a red asterisk. Columns whose headers match are mapped for you under **Columns in your File**; pick the rest from the drop-downs and leave anything you are not importing as **Ignore this column**. **Update record if already exists** is the first row — leave it ignored for a new-records import. Click **Next**.

    ![Map Columns, with First Name, Last Name, Email, Mobile Phone, Company and Job Title mapped and the other template fields set to Ignore this column](/images/kb/contacts-import-map-columns.png)
  </Step>
  <Step title="Verify Data">
    The importer checks every cell. Invalid cells are highlighted, the **Invalid** tab filters to those rows, and **Find and Replace** fixes a repeated mistake in one go. Edit in place, remove a row with its **X**, then click **Submit**.

    ![Verify Data showing one invalid row — the email cell highlighted — with the All / Invalid tabs and the Submit button](/images/kb/contacts-import-verify-data.png)
  </Step>
</Steps>

The import runs on the server; you get a confirmation on screen and the new rows appear in the table.

## Import to update existing records

The importer finds an existing record by one column per module, and only overwrites it when the row says so:

| Module | Matched on | Switch column |
| --- | --- | --- |
| Contacts (speakers, moderators, chairpersons…) | **Email** | **Update record if already exists** |
| Sponsors and Exhibitors | **Name** | **Update record if already exists** |
| Sessions | **Session Friendly ID**, or **Client Session ID** | **Update session if already exists** |

<Steps>
  <Step title="Export first">
    Add the match column and the fields you plan to change to the module view, then click **Options → Export .CSV** (or **Export .XLSX**). Starting from an export guarantees the identifiers are exactly what Sessionboard holds.
  </Step>
  <Step title="Edit the file">
    Change the values you need. Add a column named **Update record if already exists** (**Update session if already exists** for sessions) and put `TRUE` in every row you want updated. Delete the rows you are not changing.
  </Step>
  <Step title="Import it">
    Run the import as above. On **Map Columns**, map the switch column and the match column, and choose **Ignore this column** for anything you are not changing — a mapped column with an empty cell clears the value.
  </Step>
</Steps>

### Which column matches a session

- **Session Friendly ID** is the `SESS-123` ID Sessionboard assigned. It identifies exactly one session, including subsessions, and wins when both ID columns are mapped.
- **Client Session ID** is your own system's identifier. It is used when **Update session if already exists** is true and no Session Friendly ID is mapped. If more than one session on the event carries that Client Session ID, the row fails with an error naming the column instead of updating one at random.

<Note>
**Update session if already exists** is a true/false switch, not a match key. If you map an ID column onto it the row fails with an error rather than quietly creating a duplicate. Put identifiers in **Session Friendly ID** or **Client Session ID** and keep this column to `TRUE` / `FALSE`.
</Note>

## Common questions

<AccordionGroup>

<Accordion title="Will importing create duplicates?">

Not when you map the identifier. Contacts match on **Email**, groups on **Name**, and sessions on **Session Friendly ID** (or **Client Session ID**), and a row with **Update record if already exists** set to TRUE updates the existing record instead of creating one. Rows without the switch create new records, so export first and start from that file when you are updating. Contacts are shared across your organization, and a speaker who already exists is reused rather than duplicated. If duplicates already exist, [merge duplicate contacts](/contacts/merge-duplicates).

</Accordion>

<Accordion title="What order should we import in — speakers first or sessions first?">

Contacts first. The session import's **speakers**, **moderators** and **chairpersons** columns take contact email addresses, separated by commas, and a row fails with *does not exist as a contact* when an email is not already a contact on the event. Import or create the people, then import sessions with their participants, then sponsors and exhibitors.

</Accordion>

<Accordion title="Can we import last year's speakers and sessions?">

Yes. For events in the same organization, [copy sessions from another event](/sessions/copy-sessions-from-another-event) moves sessions or abstracts with optional participants and field mapping, and contacts are already shared through the organization. From another system, export to CSV and import contacts, then sessions. With Speaker CRM, past speakers stay in the [CRM](/speaker-crm/overview) and can be [added to events](/speaker-crm/crm-add-contact-to-events) without a spreadsheet.

</Accordion>

<Accordion title="The file uploads but rows fail — what do I check?">

**Verify Data** highlights the cells it cannot accept; the **Invalid** tab lists just those rows. The usual causes are a header that does not match the English field label, a phone number without a country code, a date Excel reformatted, a multi-select without the pipe separator, more than 1,000 rows, or a CSV that is not UTF-8. See [common CSV and XLSX import issues](/faq/common-csv-xlsx-import-issues-and-how-to-fix-them).

</Accordion>

<Accordion title="Our importer looks different — an upload box with a progress bar and a results table">

Your account has **Sessionboard Imports** turned on, Sessionboard's own importer. The steps are the same in a different order: drop the file, **Match your columns** (each of your columns against a Sessionboard field, with a preview of its values), choose what happens **When a row already exists** — **Create new and update existing**, **Create new rows only** or **Update existing rows only** — and click **Import N rows**. The result lists rows **Created**, **Updated** and **Failed**; rows that passed are imported, and **Download or retry failed rows** gives you just the rest to fix and re-import. You can close the panel and keep working while it runs.

</Accordion>

<Accordion title="Can we undo an import?">

Export before every update import so you have a copy to restore from. If an import went wrong, contact [support@sessionboard.com](mailto:support@sessionboard.com) with the event and the time of the import.

</Accordion>

</AccordionGroup>
