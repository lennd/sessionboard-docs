<AddOnNote label="Program Site" />

The Program Site brings program interactions together in one place: submission forms, awards, interest forms, reviewer access, and public voting ballots.

You can also surface forms from other events, so it can work as a cross-event hub when you need that.

## What the Program Site centralizes

- Call for Papers forms
- Submission forms (abstracts or sessions)
- Awards forms
- Interest and pipeline forms
- Reviewer access (evaluation plans and rounds)
- Public voting ballots (evaluation and awards rounds set to **Public voting**)

## How forms and submissions work

The Program Site does not recreate forms inside the platform. When a user clicks a form, it opens in a new window in its native interface. There is no need to rebuild or duplicate form logic.

All submissions are aggregated into a single unified view, regardless of which form they came from. Users can see submissions across interest forms, awards forms, and session or abstract submission forms, all in one place.

From this view, users can open any submission and be redirected to the original form to view their completed responses.

<Tip>
This is especially useful for events that run multiple submission forms or different workflows in parallel. Instead of sharing multiple links, the Program Site acts as one central hub for all entry points.
</Tip>

<Note>
The Program Site is optional. Teams can still use standalone form links, embed forms on their own website, or keep their existing process. The Program Site is an added layer of convenience, not a replacement.
</Note>

## Setting up your Program Site

<Steps>

<Step title="Open Program Site">

In your event, go to **Program > Site**.

![Program Site in the event navigation under Program, Site](/images/kb/8afcd9aa-image-png-Jul-08-2026-07-40-27-6523-PM.png)

</Step>

<Step title="Configure your site settings">

Click **Settings** in the top right of the Site overview. You can also use the **Quick Actions** panel at the bottom as shortcuts to jump directly to each section.

Settings is organized in four sections.

#### Site URL

Set the **Site Name**, an internal label not shown publicly, and the **Site Slug**, which defines your public portal address:

`https://sites.sessionboard.com/s/[your-slug]`

The slug supports up to 100 characters.

![Site Name and Site Slug fields in Program Site settings](/images/kb/824ff058-image-png-Jul-08-2026-07-42-07-3297-PM.png)

#### Landing page & login

Controls everything participants see before logging in.

- **Title and Subtitle**: The headline and supporting text shown on the public landing page.
- **Login Methods:** At least one must be enabled at all times:
  - **Standard Login**: Email-based. Users sign up and log in using just their email address.
  - **SSO Login:** Single Sign-On via your organization's identity provider (SAML, OIDC, etc.). Contact Sessionboard to enable this for your account.

![Landing page login methods with Standard Login and SSO Login](/images/kb/3d7b7879-image-png-Jul-08-2026-07-44-37-4053-PM.png)

**Branding:**

- **Logo:** Displayed on the landing page.
- **Gradient Start Color / Gradient End Color:** The two colors forming the background gradient.
- **Font Family:** Choose any Google Font (default: Inter).
- **Advanced:** Add custom HTML, CSS, and JavaScript for deeper customization.

![Landing page branding including logo, gradient colors, and Advanced custom code](/images/kb/9c05b581-image-png-Jul-08-2026-07-46-13-1599-PM.png)

#### Logged-in experience

Controls what participants see after logging in.

- **Title** and **Description:** A welcome message and rich-text content shown inside the portal.
- **Logo:** The logo displayed inside the portal (can differ from the landing page logo).
- **Background Image:** An image shown in the logged-in view.
- **Font Family:** Typography for the logged-in experience.
- **Primary Color**: Accent color used for section backgrounds throughout the portal.

![Logged-in experience settings with title, logo, and primary color](/images/kb/d57b036f-image-png-Jul-08-2026-07-46-49-3344-PM.png)

#### Available programs

Choose which programs are visible to visitors on your portal. You can search across all programs in your organization, select which ones to display, and drag them to reorder their appearance.

![Available Programs list with search and drag-to-reorder](/images/kb/05d8e07a-image-png-Jul-08-2026-07-53-25-1863-PM.png)

#### User information

Configure what data is collected from users when they enter the portal.

- **Required Fields:** First Name, Last Name, and Email are always collected and cannot be removed.
- **Privacy Notice:** Add a custom privacy message that will be displayed alongside the standard terms and privacy acceptance. Keep it short for the best user experience. Example: *"By submitting this form, you agree to share your information with [Organization Name], the vendor of this platform."*

![Privacy Notice field on Program Site settings](/images/kb/dda3afbc-image-png-Jul-08-2026-07-53-49-4196-PM.png)

#### Custom pages

Add custom navigation pages with your own content. These pages appear in the **header navigation** of the landing page and in the **sidebar** of the logged-in portal. Use **+ Add Page** to create them. This is useful for FAQs, instructions, or any static content you want participants to access directly from the site navigation.

![Custom Pages list with Add Page](/images/kb/f726ac4e-image-png-Jul-08-2026-07-54-40-6988-PM.png)

</Step>

<Step title="Set up reviewer access">

For evaluators, the Program Site becomes their main interface. Reviewers access it via a **magic link** sent from their evaluation plan; no admin account or platform onboarding is required.

Once logged in, reviewers can:

- See all assigned evaluation plans and rounds
- Track pending vs completed reviews
- Access all submissions they need to review

From within each submission, reviewers can:

- View submission details and participant information
- Access uploaded files
- Complete scorecards (ratings, written feedback, and more)

Admins control what metadata is visible to reviewers and which filters are available (for example: track, level, language, tags), ensuring reviewers get the right context without information overload.

<Warning>
Reviewers are granted access through their evaluation plan assignment, not through the Site settings directly. Make sure evaluators are added to their respective plans before sharing the site URL. [Learn how to add evaluators to a plan.](/evaluations/evaluation-plans)
</Warning>

</Step>

<Step title="Share the site URL">

Once configured, share the Program Site URL with your submitters and reviewers. For a public-voting round, share the copied vote link from that round — it is unlisted, so only people with the URL can open the ballot.

![Program Site overview with the public site URL ready to share](/images/kb/2d293de3-image-png-Jul-08-2026-07-55-54-2113-PM.png)

</Step>

</Steps>

## Public voting

When an evaluation or awards round is set to **Public voting**, the ballot lives on this Program Site. Copy the link from the round (**Copy link**) and share it. Voters open the URL and score submissions on that round's scorecard. The round's **Voter sign-in** setting decides whether they sign in with a magic link or SSO first, or vote immediately with no sign-in (IP address only). Rounds can also cap how many submissions each voter votes for (**Votes per voter**).

![Public voting banner with Copy link and Open on an evaluation round](/images/kb/eval-public-voting-copy-link.png)

Public voters are not invited evaluators. They are not assigned a queue under **My Reviews** — they use the vote link only. They join the round when they save a score.

![A public vote submission on the Program Site, with the scorecard and Sign in to vote](/images/kb/public-vote-eval-item.png)

Pasting the vote URL into Slack, LinkedIn, or similar shows a branded preview of the round (site logo and round name). Opening a single submission in that link shows that item. If the round uses blind review, the preview never includes a name or headshot. Search engines and AI assistants do not index these URLs.

See [Round-based evaluations](/evaluations/setting-up-round-based-evaluations) and [Managing submissions, reviewers & rounds](/awards/managing-submissions-reviewers-rounds) for how to set a round to Public voting and copy the link.

## What each user sees

| User | Experience on the Program Site |
| --- | --- |
| Submitters | All available submission forms and a unified view of all past submissions across forms |
| Reviewers | All assigned evaluation plans, pending rounds, and submissions to review |
| Public voters | The vote link for that round: sign in (when the round requires it), browse submissions, and complete the scorecard |

<Note>
The Program Site and evaluator experience are available in 5+ languages and are WCAG 2.1+ compliant.
</Note>
