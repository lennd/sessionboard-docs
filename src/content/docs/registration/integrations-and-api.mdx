**Registration → Integrations & API** shows where registration data goes and what comes back: installed apps, webhooks, Zapier, API tokens with registration access, and the latest changes other systems made through the Public API.

## Why use it

Registration rarely lives alone. Your CRM wants new registrants, your housing partner wants arrivals, and a badge or lead-retrieval partner wants the attendee list and sends scans back. This page puts every connection in one place, so you can see what has access to registration data and confirm a sync is working.

## Where registrations can go

| Destination | What it does |
| --- | --- |
| **Apps** | Registration, check-in, badge, scanning and lead-retrieval partners in the **Onsite & Expo** category. Installed apps receive registrations and send check-ins, scans and leads back. |
| **Webhooks** | Post registration, order and check-in events to your own endpoint as they happen. See [Webhooks](/integrations/webhooks). |
| **Zapier** | Send new registrations to a spreadsheet, CRM or chat without code. See [Zapier](/integrations/zapier). |
| **Public API and MCP** | Organization tokens for the Public API and the Sessionboard MCP server. See [API tokens](/integrations/api-tokens). |
| **API log** | Every Public API call and integration push, with status and payload. |

![The Apps, Webhooks, Zapier, Public API and MCP, and API log panels on Integrations & API](/images/kb/registration-integrations-destinations.png)

## Your CRM

The **CRM** panel uses your organization's CRM connection (connect HubSpot in **Apps**). Each registration goes to the event's marketing event in the CRM as registered, attended or canceled. Registrants who opted in to marketing also get their ticket, registrant type, registration status, amount and member id on their contact, in the **Sessionboard** property group. The panel shows how many registrations were sent, the last sync and any errors; **Sync now** sends them all again. Turn off **Send this event's registrations to the CRM** to stop it for this event.

<Note>
Salesforce cannot receive registrations yet. A Salesforce connection shows as not available here.
</Note>

## Public API scopes

Grant a token only the scopes a system needs:

| Scope | Gives access to |
| --- | --- |
| `read:registrations` | Forms, ticket types, registrations, orders, attendees and check-ins |
| `write:registrations` | Create and update registrations and orders from your own systems |
| `read:expo` | Booths and sponsorships |
| `write:expo` | Update booths and sponsorship orders |

![The Public API scopes panel listing read and write scopes for registrations and Expo](/images/kb/registration-integrations-scopes.png)

Registration and Expo endpoints read and write the same records as the admin, and every write is in History. The developer guide is [Registration and Expo in the Public API](https://sessionboard.mintlify.app/guides/registration-and-expo).

## See what is connected

- **API tokens for this event** — organization tokens with registration or Expo scopes, whether they reach every event or this one, and their scopes. **API docs** opens the developer guide.
- **Webhooks and onsite** — whether webhooks are set up for the event and which events they send, and which onsite jobs a partner runs. **Change** opens [Do it yourself or a partner](/onsite/diy-or-partner).
- **Latest Public API writes** — the last 50 changes other systems made to this event's registration.
