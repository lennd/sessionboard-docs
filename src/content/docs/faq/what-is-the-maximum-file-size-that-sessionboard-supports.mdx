Most uploads in Sessionboard accept files up to **5 GB**. The size submitters are *told* on a form, and the size a given uploader will *enforce*, depend on where the file is collected.

## Submission-form file questions

On a session submission form, **Customize Question → Maximum file size** is the size advertised under the field (for example “Images only (up to 2 MB)”). Leave it blank to inherit the field default, up to **5 GB**. Session **Files** settings and [speaker headshot limitations](/events/event-details) do not change that hint.

On **Headshot** and **Logo**, **Help Text** you write is the only line under the field. Other file fields still show the type-and-size hint even when they also have help text.

SVG and HTML files are not accepted here — the file picker does not offer them, and an upload of either type is rejected. See [Where SVG and HTML are blocked](#where-svg-and-html-are-blocked) below.

See [Session submission forms](/sessions/submission-forms).

## Restrict a file question to certain file types

**Customize Question > Accepted file types** limits a file question to the formats you want. Tick any of PDF, PPT, Image, Video, Audio, Word, Excel, ZIP, PNG, JPEG, GIF, SVG, or MP4. Leave every box unticked to accept anything — that is the default, and it is what a question with no list set keeps doing.

The same control sits on a global field in the field library's **Edit Field** panel, and both write the same setting. Either way, submitters see the accepted types in the hint under the field and their file picker filters to them.

The list applies to awards entries too, on the public awards form and in the organization portal alike.

Sessionboard reads the file's **contents**, not just its name. Renaming a JPEG to `entry.pdf` does not get it past a PDF-only question — the upload is rejected, and the message says what the file actually is.

A few formats can't be identified from their contents. Word, Excel, PowerPoint, and ZIP files share one container format underneath, and plain text and CSV have no signature at all, so for those the file extension is what gets checked.

SVG and HTML stay blocked on submitter-facing forms even if you tick SVG — see [Where SVG and HTML are blocked](#where-svg-and-html-are-blocked).

## Headshots and logos

[Speaker headshot limitations](/events/event-details) and the matching logo controls live in **Settings → Record Settings**. When **Limit file size** is on, the photo editor refuses files over the cap you set (10 KB to 5 GB). When that limit is off, the editor uses the 5 GB platform ceiling.

Those event limits do not rewrite the form hint. A blank **Maximum file size** still reads “up to 5 GB” even if Record Settings has a tighter cap.

## Session Files

Presentations and other session content collected under **Sessions → Settings → Files** use a **1.95 GB** per-file cap. That setting does not apply to file questions on a submission form. See [Enable, upload, & download files](/sessions/enable-upload-download-content).

## Where SVG and HTML are blocked

SVG and HTML are script-bearing documents, so Sessionboard rejects them on the upload surfaces where one person submits a file that other people are later invited to open:

- **Session submission forms** — file questions on a call-for-papers or session submission form.
- **Awards submissions** — file fields on an awards entry, both on the public form and in the organization portal.
- **The session Files tab in the speaker portal** — uploads made by a participant. Event admins working in the same place are deliberately exempt, because uploading an SVG logo is a normal thing for an admin to do.

On those surfaces the check reads the file's actual content rather than trusting its name, so renaming an SVG or HTML file to another extension does not get it through.

Branding and asset uploads — event and organization logos, headshots, and similar — accept SVG on purpose. Any SVG that Sessionboard stores has scripts stripped out of it first.

## File requests and other uploads

File requests and most other content uploads accept files up to **5 GB**. Event admins can set a lower maximum for some of those uploads in **Settings → Record Settings**.

Acceptable file types include Word, Excel, PowerPoint, PDF, image, video, and audio — unless the field or event setting narrows the list.
