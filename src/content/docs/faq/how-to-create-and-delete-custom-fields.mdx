## Create a field

<Note>
Once a field has been saved, its **Field Type** cannot be changed. To change the type, create a new field and archive or delete the old one.
</Note>

Fields live in two places:

- **Organization Settings > Library > Fields** — fields for the whole organization, on the **Contact**, **Group**, **Session** and **Event** tabs. Fields created here are **Global**: their data follows the record across every event.
- **Event Settings > Fields** — the fields this event uses, on the **Contact**, **Group** and **Submission** tabs. Fields created here belong to this event.

1. Open the page and select the tab for the kind of record the field belongs to. Within a tab, **Profile**, **Communication**, **Attribute** and **Custom** narrow the list, and **Hidden Fields** holds anything archived.

   ![Library > Fields at the organization, on the Session tab](/images/kb/fields-library.png)

2. Select **Add Field** in the top-right corner.

3. In the **Create … Field** panel, enter a **Name**, choose the **Field Type** — Text, Text Area, Rich Text, Number, Currency, Percent, Date, Date & Time, Time, Dropdown, Checkbox, Tree, Countries, Email, Phone, URL, File, Signature or Formula — and fill in the settings that type offers — a **Maximum Length** for text, the options for a dropdown (turn on **Allow users to create new options** to let submitters add values that are not in the list; new values are added for everyone). On an event's Fields page, **Field Level** chooses between an **Event Field**, which exists only on this event, and a **Global Field**, whose data follows the record across every event in the organization; at the organization level every field is global. A **Formula** field calculates a number from other fields on the same record and cannot be saved until the expression is valid; see [Create a formula field](/settings/formula-fields) for the builder, the **Write** editor, and the limits. To format text, calculate into an editable field, or set fields when values match, see [Create a field rule](/settings/field-rules). Turn on **Contains Personal Data** to mask the field's values in AI queries and shared reports.

   ![The Create Session Field panel — Name, Field Type, Field Description, Maximum Length, Field Level and Contains Personal Data](/images/kb/fields-add.png)

4. Select **Save Changes**. The field appears in the list under the tab you chose and is ready to add to forms, tables and portals.

<Tip>
Create custom fields to track review status, priority, or other admin-only details, then hide them from roles that should not see them with [field permissions](/event-team/invite-manage-event-team-members#field-permissions-who-can-see-or-edit-each-field).
</Tip>

## Archive a field

When a field is no longer needed, **archive** it rather than deleting it. An archived field is hidden from form builders, field pickers, column pickers, and public forms, but nothing stored in it is lost: existing values stay visible read-only on each record, and you can bring the field back at any time.

1. Open **Library > Fields** (or the event's **Settings > Fields**) and find the field — the **Custom** filter and the search box narrow the list.
2. Open the row's **⋯** menu and select **Archive**.
3. Confirm in the **Archive this field?** dialog.

<Note>
Make sure you are on the right tab — a session field is not listed under **Contact**.
</Note>

![The Custom filter on an event's Submission fields, listing the event's custom fields](/images/kb/fields-event-custom.png)

Archiving from **Library > Fields** hides the field across the whole organization. To hide a field for one event only, archive it from that event's **Settings > Fields** instead; it stays available on your other events.

Archived fields are listed on the **Hidden Fields** tab of the same page, with who archived them and when. Select **Restore** on a row to make the field available again. A field archived organization-wide is restored from Library > Fields, not from an event. You need the *Can manage fields* permission for that module (for example *Can manage contact fields*) to archive, restore, or see the Hidden Fields tab.

System fields can be archived too, but not deleted. Five fields can never be archived, because Sessionboard relies on them — session **Title** and **Description**, and contact **First name**, **Last name**, and **Email**. You can still rename them: open the field, change **Name**, and save; the other settings stay locked. The dropdown options on **Annual revenue** and **Organization structure** are editable as well.

## Delete a field

Deleting removes a custom field and everything stored in it. Prefer archiving unless the field was created by mistake. System fields cannot be deleted.

Open the field first. If it is used in a formula or a Field Rule, the sidebar shows **Used in formulas** and **Field Rules**. Replace that field in those expressions or rules before you delete it. After you delete a source, the last stored result stays on the record and the math does not run again until you fix the expression.

Find the field, open its **⋯** menu and select **Delete**.
