Every event you create stays in your organization — past, current or future — so that last year's speakers, sessions and forms remain there to report on, clone and search. Two things keep the list manageable: the **Upcoming** filter, and archiving.

## Why use it

Teams that run many events year over year end up scrolling past last year's conferences to reach this year's. Archiving takes finished events out of the Events page and the switcher without deleting anything or breaking a single portal, embed or integration, so the workspace shows what is live while the history stays there for reporting, cloning and speaker records.

## Why use it

Archiving lets you hide past events from the Events page, the sidebar switcher, and event pickers without deleting any data or disrupting anything that is still live. Speaker portals, embeds, integrations, and the public API for an archived event continue to work exactly as before. When you need to revisit a past event — for year-over-year reporting, cloning, or team access — you can surface it instantly with the Show archived toggle and unarchive it with one click.

## Keeping the events list tidy

On the organization's **Events** page:

- **Filter** narrows the list to **Upcoming**, **Past** or **Synced** events. Past events leave the Upcoming view automatically once their end date passes; nothing needs to be done to them.
- The search box finds an event by name.

## Archived events

Ask your Customer Success Manager to archive an event you are finished with. An archived event:

- leaves the organization's **Events** page, the sidebar event switcher and event pickers;
- keeps working otherwise — its URL, portals, embeds, integrations and the public API are untouched, and it still counts in reports and portfolios;
- shows a banner inside the event, *This event is archived. It is hidden from event lists but otherwise works as usual.*, with an **Unarchive** button for anyone whose role has **Update Event Settings**.

To find archived events, open **Filter** on the **Events** page and tick **Show archived**; archived events are listed with an **Archived** badge and the list shows an **Including archived** chip. The sidebar event switcher has a **Show archived** switch that does the same. Cloning an archived event produces a normal, unarchived event, and the clone picker keeps listing archived events so you can clone last year's.

## Why past events stay

- Contact history and the [New/Returning badge](/faq/what-does-the-new-returning-badge-on-a-contacts-profile-indicate) are built from past events.
- [Cloning an event](/faq/clone-an-event) copies its forms, tasks, templates and settings into next year's.
- Reports and audits can look back across years.

## Deleting an event

If an event was created by mistake, a user with the **Delete Events** organization permission can open the event's menu on the Events page and choose **Delete Event**. The event and everything in it — sessions, contacts, files, forms — is hidden from lists and dashboards rather than erased. Restoring is done by Sessionboard support, so contact [support@sessionboard.com](mailto:support@sessionboard.com) if a deleted event needs to come back.
