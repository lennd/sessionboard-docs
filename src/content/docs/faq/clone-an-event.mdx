Cloning copies an event's structure — forms, portals, tasks, settings — into a new event, so a recurring conference does not have to be rebuilt each year.

There are two ways to get one. Starting with an empty event instead? See [start a new event from scratch](#start-a-new-event-from-scratch).

## Why use it

If your conference runs every year, cloning lets you start the next edition from last year's forms, portals, tasks and settings rather than building them again. You choose which parts come across, from contacts and sessions to email templates and reports. A clone into a test event is also a safe place to try a change before you make it for real.

## Clone it yourself

When **Clone Events** is switched on for your organization — ask your account team or [support@sessionboard.com](mailto:support@sessionboard.com) if you do not see it — event admins can clone from the organization's **Events** page: open the event's menu and choose **Clone Event**.

The sidebar asks for an **Event Name** and a **New Start Date** and **New End Date** (the original dates are shown for reference), then the copy options: Contacts, Sponsors, Exhibitors, Views, Submission Forms, Sessions, Program Settings (Files, Embeds, Tracks, Format, Tags, Levels, Languages, Locations, Statuses), Evaluation Plans, Custom Portals, Event Team, Email Templates, Email Campaigns, Tasks, Forms, File Requests, Shared Files, Resources, Application Forms and Reports. **Select Default** ticks the usual set; **All** and **None** are there too. Click **Clone Event** — the job takes a few minutes and you are taken to the new event when it finishes. The table below explains what each option carries.

## Ask support to clone

Email [support@sessionboard.com](mailto:support@sessionboard.com) with:

- The event you want copied and the name of the new event
- Which elements to copy — see the table below
- Whether the new event should keep the original's portal branding (logos, background images, colours, custom CSS) or start fresh with its own

The team runs the clone and lets you know when the new event is ready. Cloning into a different organization is always done by support.

## What gets copied

![The Select copy options list in the Clone Event panel, with Submission Forms, Sessions, Program Settings, Evaluation Plans and Event Team ticked](/images/kb/clone-event-copy-options-forms-team.png)

| Element | Notes |
| --- | --- |
| Contacts | Not duplicated in your CRM — they are referenced from the organization. |
| Sponsors | Adds the original event's sponsors to the clone. |
| Exhibitors | Adds the original event's exhibitors to the clone. |
| Views | Saved views of contacts and sessions. If you skip contacts or sessions, views may reference custom fields that are not there. |
| Session submission forms | Form questions only, not the submissions. A form still on the older v1 builder is converted to v2 on the copy — the original stays as it was. Check participant role limits on the copy if the original had a speaker limit. |
| Sessions | Includes speakers, tags, tracks, and locations. Reset start and end times to your new dates. |
| Session settings | Rooms, tracks, tags, format, level, languages. Must be included for sessions to copy correctly. |
| Session file approval workflow | Comes with the **Submission Forms** option when the original event requires [approval for session files](/sessions/file-approvals). Conditions on an upload slot, track, format, level or sponsor tier point at the copy's own items; a value with no match in the copy is dropped, so check **Applies to**, step conditions and **Route to** rules before files arrive. Reviewers named as people stay only if they are on the copy's event team, so include **Event team** too. Reviewers chosen by role keep their roles. Files in review, decisions and release-time history are not copied. |
| Evaluation plans | Copied as **closed**. Review the setup and set a new due date to reopen them. A plan still on the older v1 builder is converted to a single-round v2 plan on the copy; a v1 plan that uses personas is copied as-is and keeps its **v1** badge on the Evaluation Plans list, where you can convert it yourself. When **Event team** is also copied, the plan's evaluators come with it, but no submissions are assigned to them and no reviews are copied. Assignment rules are copied without having run, so run them once the new event has submissions. |
| Embeds | Settings for the newer Embeds 2.0 builder are always on in the copy. |
| Custom portals | Portals based on custom fields may need to be reconfigured. |
| Event team | All non-portal users — admins, evaluators, and so on. |
| Email templates | Templates created in the original event. |
| Email campaigns | Off by default. Every Send campaign is copied as a **Draft** — subject, body, audience, theme and recipient filters re-pointed at the new event, with nothing from the send: no schedule, history, analytics or approval. Filters that match nothing in the copy are dropped and listed as warnings on the draft; automations are not included. See [Copy campaigns from another event](/communications/email-campaigns#copy-campaigns-from-another-event). |
| Tasks, forms, file requests | Copied into the new event. |
| Shared files and resources | Uploaded files and wiki pages. |
| Reports | Custom reports. |
| Applications | Application forms. |
| Floor maps | Always copied, as **drafts**: halls, backgrounds, scale, booths with their numbers, types and list prices, zones, facilities, walkways and images. Booth sales start fresh — every booth is **Available** with no exhibitor or hold — and a zone linked to a session room points at the copy's room, or loses the link when **Session settings** are not copied. Images keep their art but not their sponsor. Version history starts again. Publish the maps when the new edition's hall is ready. See [Lay out booths on the floor plan](/expo/floor-plan). |
| Sites | The event's Sites, with all settings, branding, and custom pages. Each cloned site gets a placeholder URL slug ending in "-copy" — set the real slug in Site Settings — and no programs are linked, so publish the new event's programs yourself. |

## Clone into a different organization

The team can also clone an event into another Sessionboard organization you have — for example, to move a sandbox event into your production organization. Both organizations must be in the same data region. Say which organization should receive the clone when you email support.

The new event belongs entirely to the receiving organization and keeps no links to the original:

- **Contacts** are matched by email to people already in the receiving organization. Anyone without a match is added as a new contact there.
- **Companies** are added as new records in the receiving organization.
- **Custom fields and record types** are matched by name in the receiving organization, or created there if they do not exist yet.
- **Files** are copied, so the new event does not depend on the original's uploads.
- **Event team** members keep their seats only if they already belong to the receiving organization — unless you ask the team to add them.

Some things stay behind:

- Reviews, scores, and reviewer assignments
- Submission history and form responses
- Notes, comments, and activity
- Sent messages and email logs (copied email campaigns keep their hand-picked recipients only within the same organization — a clone into another organization drops them)
- Attendees, registrations, orders, and payments
- Awards programs
- Booth sales on floor maps (holds, reservations, sold booths and exhibitor assignments)
- Dispatch and Advocacy campaigns
- Media, integrations, API keys, and webhooks
- SSO login settings

<Note>
After a clone into another organization, check the receiving organization's payment gateway, email sender domain, SSO, and branding — those belong to the organization, not the event.
</Note>

## Check the branding after cloning

If the clone kept the original's branding, the new event shows a banner listing what came from the source event, so nothing carries over unnoticed. It covers:

- **Event branding**
- **Portal Home**
- **Portal Login**
- Per-portal appearance settings

<Warning>
This is the failure worth avoiding: a cloned event goes live with last year's logo in a speaker portal because nobody thought to look. Work through the banner before you invite anyone.
</Warning>

<Tip>
Cloning is also useful for a dry run — ask support to clone into a test event, try a change, and throw it away.
</Tip>

## Start a new event from scratch

To create a new event or add an event, click **Add Program** — on the organization's **Events** page, or under the **+** button in the header. Pick what you are creating from the four cards — a **Conference**, an **Awards** program, a **Webinar** or a **Field event**; the page title follows your pick (**New conference**, **New awards program**, …).

![The New conference page with the Conference, Awards, Webinar and Field event cards, then Start from and The basics](/images/kb/add-program-page.png)

For a conference, **Start from** either **A blank event** or **A copy of an existing event** (pick the **Event to copy** and **What to bring over** — the [clone options](#what-gets-copied) above). Fill in **The basics** — **Name**, **Starts**, **Ends**, **Time zone** and, for a blank event, **Website** — and click **Send request**. New conferences are set up by your Customer Success team, so this sends them a request rather than creating the event on the spot — it is a form on the page, not a support chat; a copy you are allowed to [clone yourself](#clone-it-yourself) is created straight away instead.

A conference request also asks **Help us set it up** — the same questions as onboarding: what you are managing (abstracts, sessions or both), roughly how many speakers and sessions, whether submissions are evaluated and by how many people, and when the call opens and closes. Rough answers are fine and every one is optional; they let your Customer Success Manager check your plan covers the event and build it toward your dates. **Anything else for our team?** takes a free-text note.

![The Help us set it up questions on a conference request — what you are managing, roughly how many speakers and sessions, whether submissions are reviewed, the call for sessions dates and a note — above Send request](/images/kb/add-program-help-us-set-it-up.png)

What happens next:

- You get a confirmation email from **success@sessionboard.com**. Replying to it reaches the Customer Success team.
- The request is listed on the **Add Program** page until it is handled.
- When the event is ready you get a second email, the event appears in your **Events** list, and you are already on its team — the first stop inside it is [Event details](/events/event-details). If the team declines the request, you get an email instead, with their reason when they give one.

[Webinars](/webinars/overview) are included with **CRM**: if your organization has CRM they are created straight away; if not, the page shows what they do and a **Talk to us about CRM** button ([If Webinars is locked](/webinars/overview#if-webinars-is-locked)). [Field events](/field-events/overview) are a [Beta](/get-started/early-access). If your organization has it, they are created straight away; if not, the page shows what they do with a **Request beta access** button (people without the **Manage Early Access** permission are asked to have an org admin request it). **Awards** opens a panel that starts the awards setup wizard — see [Awards: getting started](/awards/getting-started#creating-a-new-program).
