Cloning copies an event's structure — forms, portals, tasks, settings — into a new event, so a recurring conference does not have to be rebuilt each year. You can do it yourself; no support request needed.

## Clone an event

<Steps>

<Step title="Open your events list">

Go to **Org → Events** and find the event you want to copy.

</Step>

<Step title="Choose Clone">

Pick **Clone** from the event's actions. The clone panel opens.

</Step>

<Step title="Select what to copy">

Tick the elements you want under **Select copy options** — see the list below. Sessionboard remembers your selections for next time.

</Step>

<Step title="Decide about branding">

Leave **Start with this event's own branding** unchecked to carry the original's portal branding over as-is. Tick it to clear logos, background images, colours, and custom CSS from the copied portals and Portal Home, so they follow the new event's branding instead.

</Step>

<Step title="Start the clone">

Click **Clone Event**. Cloning runs as a background job and reports progress; larger events take longer.

</Step>

</Steps>

## What gets copied

| Element | Notes |
| --- | --- |
| Contacts | Not duplicated in your CRM — they are referenced from the organization. |
| Sponsors | Adds the original event's sponsors to the clone. |
| Exhibitors | Adds the original event's exhibitors to the clone. |
| Views | Saved views of contacts and sessions. If you skip contacts or sessions, views may reference custom fields that are not there. |
| Session submission forms | Form questions only, not the submissions. |
| Sessions | Includes speakers, tags, tracks, and locations. Reset start and end times to your new dates. |
| Session settings | Rooms, tracks, tags, format, level, languages. Must be selected for sessions to copy correctly. |
| Evaluation plans | Copied as **closed**. Review the setup and set a new due date to reopen them. |
| Custom portals | Portals based on custom fields may need to be reconfigured. |
| Event team | All non-portal users — admins, evaluators, and so on. |
| Email templates | Templates created in the original event. |
| Tasks, forms, file requests | Copied into the new event. |
| Shared files and resources | Uploaded files and wiki pages. |
| Reports | Custom reports. |
| Applications | Application forms. |

## Check the branding after cloning

If you left the branding option unchecked, the new event shows a banner listing what came from the source event, so nothing carries over unnoticed. It covers:

- **Event branding**
- **Portal Home**
- **Portal Login**
- Per-portal appearance settings

<Warning>
This is the failure worth avoiding: a cloned event goes live with last year's logo in a speaker portal because nobody thought to look. Work through the banner before you invite anyone.
</Warning>

<Tip>
Cloning is also useful for a dry run — clone into a test event, try a change, and throw it away.
</Tip>
