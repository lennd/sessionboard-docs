A role is a set of switches, grouped by module. This page lists the groups you'll find on the **Permissions** tab of **Event Team**, what actions each one has, and how a role ends up seeing or not seeing a page. For the roles themselves and how to build one, see [Invite and manage event team members](/event-team/invite-manage-event-team-members).

## How a role works

- **Default roles can't be edited.** **Duplicate** one and change the copy, or choose **Create new role** and start with everything off. **All On** and **All Off** are shortcuts.
- **Each switch stands alone.** Turning on a create, update or delete switch doesn't turn on the view switch. Give **view** whenever you give any other action in a module, or the person has nothing to open.
- **Changes save as you make them.**
- **A session filter** narrows a Session Manager role to certain tracks or forms. It doesn't add permissions. See [Roles with a session filter](/event-team/invite-manage-event-team-members#roles-with-a-session-filter).

## What each module offers

The grid groups switches by module, with a count such as **Sessions 3/6** on each group. The actions below come from the permission set the product checks. Most modules have view, add, edit and delete. The extra actions are the ones worth knowing about.

| Module | Actions beyond view, add, edit and delete |
| --- | --- |
| **Sessions** | The sessions list and profiles. See the grid for the exact set on your event. |
| **Speakers** | Export, and managing speaker fields. |
| **Contacts** | Export, managing fields, managing global fields, seeing a person's own value, and creating, editing and deleting saved views. |
| **Sponsors, Exhibitors** | The same record actions. Contact assignment, portal access and tasks need the full Sponsors Pro or Exhibitors Pro module on the event. See [Create sponsor groups & contacts](/sponsors-exhibitors/sponsors). |
| **Evaluation Plans** (the review plans) | **Can promote sessions**, viewing assigned reviews, exporting. A custom role needs **Can view sessions** to use any of them except viewing assigned reviews. |
| **Submission forms** (Program → Forms) | View, add, edit and delete. Duplicating a form needs the add permission. |
| **Program settings** | View, add, edit and delete. |
| **Agenda** | View, and managing drafts. |
| **Embeds, Files** | View, add, edit and delete. |
| **Portals, Portal tasks** | View, add, edit and delete. **Portals** also has **impersonate**, which is what **Preview as reviewer in portal** needs. |
| **Reports** | View, add, edit and delete for reports, and the same four for dashboards, plus Ask access to reports. |
| **Emails** | View, managing email templates, and the campaign actions: view, create, send, edit and delete. |
| **Registration, Marketing** | Their own module permissions. |
| **Credit Claiming** | View, and manage. The two Credit Claiming roles use only this. See [Credit Claiming roles](/sessions/credit-claiming-roles). |
| **Contracts** | View, add, edit and delete. See [Contracts permissions](/speaker-crm/contracts-permissions). |
| **Users** | Seeing the team, inviting, and editing or removing users all sit under one **manage users** permission. |
| **History** | View. |
| **Settings** | Event and organization settings. |

<Note>
The wording on each switch is on the grid itself. If a switch you need isn't listed here, open the **Permissions** tab and read the group; that is the source of truth for your event.
</Note>

## What disappears from the sidebar

Turning off a module's **view** switch hides its page from the event sidebar for these:

- **Sessions** (and **History**, which follows it)
- **Speakers**
- **Sponsors** and **Exhibitors**
- **Contacts** (**People**)
- **Portals**
- **Reports**
- **Event Team** (from the manage-users permission)

Everything else stays in the sidebar. The page opens, and the actions inside it are blocked, or buttons are disabled with a tooltip that names the missing permission.

## Hide Publish (or another module) from a role

The sidebar only hides the pages in the list above. **Publish** isn't on it, so there is no role setting that removes Publish from the sidebar. To stop a role changing it, build a custom role with the **Embeds** and **Files** switches for edit, add and delete turned off, and leave view on only if they need to look.

Check the result before you rely on it: open the **Event Team** row for a test user with that role, and see what they can open. If you need the whole **Publish** group hidden from a role, tell your Customer Success Manager so it is raised as a request.

## A role is missing from the invite list

Default roles that your plan or event doesn't use may not appear when you invite someone. Open the **Permissions** tab and confirm the role exists there, then try inviting from **Event Team** again. If a default role shows on the **Permissions** tab but not in the invite picker, contact [support@sessionboard.com](mailto:support@sessionboard.com) with the role name and event.
