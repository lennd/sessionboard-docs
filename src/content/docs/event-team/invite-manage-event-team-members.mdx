Sessionboard allows event organizers to collaborate with teammates through customizable roles and permissions. This guide will walk you through:
- How to invite team members to your event
- How to view and manage permissions for default roles
- How to create custom role
- How to control field permission (who sees/edits which fields)
- How to limit which session statuses a role can set
- How to apply roles and field settings to many events at once

## Inviting team members
Within your event, select the Event Team module in the bottom left-hand navigation panel and select the Invite User button.

![Inviting Team Members](/images/kb/0224fef8-image-png-Jan-30-2026-03-38-18-4217-PM.png)

![Within your event](/images/kb/c80f076a-image-png-Jan-30-2026-03-41-04-1770-PM.png)

| Complete all required fields for the team member you wish to invite to your event |  |
| --- | --- |

💡NOTE: Tags can be assigned to specific users and leveraged when creating and assigning users to evaluation plans. Learn more on how to create an Evaluation Plan.

![Inviting team members](/images/kb/98d464b0-Screenshot-2024-12-11-at-2.16.47-PM.png)

| Once complete, select the Invite User button to create the user and send them an invitation email. |  |
| --- | --- |

💡NOTE: If the user is a Session Manager or Evaluator Session Manager, you will be instructed to select the Next button to assign them a filter.

![Selecting the sessions a Session Manager will be responsible for](/images/kb/42408107-image-png-Jan-30-2026-03-43-26-6916-PM.png)

​Assigning a filter will restrict the sessions and speakers the team members will be able to see and manage.

![Assigning a filter will restrict the sessions and speakers the team members will be able to see and manage](/images/kb/1dd039df-image-png-Feb-24-2026-11-33-39-1709-PM.png)

A filter can use **Status**, **Formats**, **Tracks**, **Levels**, **Languages**, **Tags**, any custom dropdown session field, or **Source**. **Source** limits the team member to sessions by where they came from — the submission form they were submitted through, or **Manual** for sessions added by hand or imported without a form. Pick several values on one row to match any of them; add rows to require all of them. The preview under the filter counts how many sessions match.

### Manage existing users
For an individual team member, you can complete the following actions:

![Manage Existing Users](/images/kb/2c0278f3-image-png-Jan-30-2026-03-44-52-5980-PM.png)

- **Edit:** Change a user's name or permission type.
- **Copy Invite URL:** If a user still needs to create an account in Sessionbaord, copy the invite URL to share with them. This is unique per invited user.
- **Resend Invite:** If a user still needs to create an account in Sessionbaord, resend the invite email. This is a unique email invited user.
- **Remove:** Remove a user from the associated event.
- **Unlock Account:** Once an incorrect password is entered five times, a user's account will be locked. Using actions, admins may unlock an account and prompt an automatic email to be sent with a link to the user where they may reset their password.

## Custom Roles

### Create custom roles
If none of the default roles suit your needs, Admins may create custom user roles.

💡Note:
- When creating a custom role, users must have at least VIEW privileges on Sessions to be able to access the below Evaluation Plan functions EXCEPT "View Assigned Evaluations".
- When Portal Tasks are enabled, users will receive automated emails when new file request messages are sent.

Under **Evaluation Plans**, **Can promote sessions** controls who may promote submissions to the next round of a funnel evaluation plan — from **Sessions → Submissions**, the session profile, or the plan's **Rounds** tab. Admin and Admin Lite have it; Session Manager and Evaluator Session Manager do not, so duplicate one of those roles and turn it on to hand promotion to a session manager. Without it, **Promote** is disabled with a tooltip naming the permission. Demoting and moving back a round are not gated by it. A team member with a session filter can only promote sessions inside their filter.

![Create custom roles](/images/kb/74534cf3-Screenshot-2025-02-07-at-6.04.37-PM.png)

### Delete custom roles
💡NOTE: ONLY custom profiles can be deleted.
1. Hover over the custom profile you would like to delete and select the three vertical dots to the right of the profile name to display the Delete option. ​

   ![Delete Custom Roles](/images/kb/03ae0f24-image-png-Jan-30-2026-04-01-51-0694-PM.png)

2. Within the pop-up window, select an existing profile (either custom or default) to assign to users who have the user type that you are deleting.

   ![Within the pop-up window](/images/kb/5d9e3f80-image-png-Jan-30-2026-04-02-20-2336-PM.png)

3. Once complete, select the Delete button.

### Duplicate roles
💡Note: Default & custom profiles can be duplicated

Hover over the profile you would like to delete and select the three vertical dots to the right of the profile name to display the Duplicate option.

![Duplicate Roles](/images/kb/b48f68d5-image-png-Jan-30-2026-04-03-03-5044-PM.png)

## Field permissions (who can see or edit each field)

Use field-level permissions to limit sensitive data and keep teammates focused only on what they need.

Where: Event Team → Permissions → Role → Fields

![Field permissions](/images/kb/da64218d-image-png-Jan-30-2026-04-05-30-6711-PM.png)

**How to configure**

1. Use the search bar to find a field, or scroll the list.
2. Set access per field:
   - View (Default) – user can see the field, but cannot change it.
   - Lock – user can see, but cannot update the field. Locking the session **Speakers** field also locks the session's participants: the role can see who is on a session but cannot add, remove, or reorder speakers, chairpersons, moderators, sponsors, or exhibitors.
   - Hide – field is hidden for this role in UI.

   ![Hide – field is hidden for this role in UI](/images/kb/de1c9011-image-png-Jan-30-2026-04-05-57-3364-PM.png)

3. Repeat for both Session and/or Group Fields as needed.
4. Changes are saved automatically.

**Tips & best practices**

- Start from a copy of a similar role or custom roles, then adjust field access to fine-tune access for vendors, volunteers, or reviewers.
- Hide Personal Identifiable Information (e.g., phone, compensation) from roles that don’t need it.
- Admin roles automatically retain full visibility and edit rights.

## Limit which statuses a role can set

Use the **Statuses** tab to control which session statuses people in a role can move a session into — for example, let track chairs send sessions to an accept queue but leave the final **Accepted** and **Declined** decisions to you.

Where: Event Team → Permissions → Role → Statuses

![The Statuses tab for a custom role, with Limit which statuses this role can set turned on and some statuses switched off](/images/kb/role-statuses-tab.png)

1. Select a custom role. Default roles are read-only here, as on the other tabs — duplicate one to restrict it.
2. Turn on **Limit which statuses this role can set**. Every status, including your custom statuses, starts switched on, so nothing changes until you switch one off.
3. Switch off each status the role should not set. Changes save automatically.

Turn **Limit which statuses this role can set** off again to let the role set any status.

What people in a limited role see:

- **Status pickers only offer allowed statuses** — on the session profile, in the Sessions and Submissions tables, in bulk edit, and when adding a session. A session's current status still shows even if the role cannot set it.
- **They still see every session and every status.** The limit only covers moving a session *into* a status; saving a session without changing its status is always allowed, and new sessions can always start as **Pending**.
- **Refused changes name the status.** If a change reaches Sessionboard another way — an import, a bulk update, Team Lead, or the public API — it is refused with a message naming the status, for example *Your role is not allowed to set the session status "Accepted"*. In an import or bulk update, only that row fails; the rest go through.

The event **Admin User** role and organization Admins can always set any status, and changes Sessionboard makes itself (such as integration syncs) are not limited.

## Apply roles to many events at once

To copy custom roles, field settings, or team role assignments from one event to many others in your organization, use **Org Settings > Bulk Permissions**. See [bulk-apply permissions across events](/event-team/bulk-apply-permissions-across-events).

## Common questions

<AccordionGroup>

<Accordion title="Which role should each teammate get?">

Start from the default roles and read their permission grids on the **Permissions** page before creating anything custom. Give full event control to admins; give people who run part of the program a **Session Manager** or **Evaluator Session Manager** role with a **filter** (by track, format, status, tag, custom dropdown, or the form a session came from) so they see only their sessions and speakers; give reviewers no more than **View Assigned Evaluations** and view on Sessions. Organization-level team members are all Admin Users ([inviting organization team members](/speaker-crm/inviting-organization-team-members)); use event-level roles for anything finer.

</Accordion>

<Accordion title="Can we restrict what a role sees or edits — specific fields, forms, or actions?">

Yes, in three layers. A **custom role** ([create custom roles](#create-custom-roles)) sets view, create, edit, and delete per module and per action, including who may promote sessions between evaluation rounds. **Field permissions** ([who can see or edit each field](#field-permissions-who-can-see-or-edit-each-field)) then set each session and group field to view, lock, or hide for that role, which is how you keep compensation, phone numbers, or internal notes away from volunteers and reviewers. **Status permissions** ([limit which statuses a role can set](#limit-which-statuses-a-role-can-set)) decide which session statuses the role can move a session into. Admin roles always keep full access.

</Accordion>

<Accordion title="What can evaluators, track chairs, and reviewers see?">

Only what their role and assignments allow. An evaluator sees the submissions assigned to them in their review portal, with the fields the plan makes visible ([reviewer view configuration](/evaluations/setting-up-round-based-evaluations#reviewer-view-configuration)). A track chair who must also accept or decline needs a Session Manager–type role with a filter on their track, or a custom role with edit on Sessions. The side-by-side comparison is in [what access do evaluators have?](/faq/will-evaluators-have-the-same-access-to-my-event-that-i-do-as-an-admin).

</Accordion>

<Accordion title="How is team access different from portal access?">

Team members are invited from **Event Team** and log into the admin app with a role. Speakers, sponsors, and exhibitors are **contacts and groups** who use the portal; they hold the **Portal User** role automatically and never see the admin app. To give a speaker admin access, invite them as a team member as well. Portal access itself is granted from Contacts ([grant portal access to a contact](/faq/how-to-grant-portal-access-to-an-event-contact)).

</Accordion>

<Accordion title="Someone cannot log in or never received the invite">

Use **Copy Invite URL** or **Resend Invite** from the team member's actions if they have not created an account yet, and **Unlock Account** after five wrong passwords. Share [new user login instructions](/event-team/new-user-login) and [reset password](/event-team/reset-password-user-instructions) with them. If your organization uses [single sign-on](/integrations/sso), they sign in through your identity provider instead.

</Accordion>

<Accordion title="Does access carry across events?">

Event roles are per event: invite the person to each event they work on, or add them at the organization level if they should reach every event as an Admin User. [Cloning an event](/faq/clone-an-event) copies the event team (all non-portal users) along with the structure and settings. To bring roles, field settings, or role assignments in line across events that already exist, use [Bulk Permissions](/event-team/bulk-apply-permissions-across-events).

</Accordion>

</AccordionGroup>
