A task is a plain action item — register for the event, book your hotel, confirm your travel dates. You create it once in the **Tasks** library, put it on one or more portals, and every person in those portals sees it on their to-do list with its due date. Who has finished shows up as a column in your contacts table, so tracking is a view, not a report.

<Warning>
If a task sends people to another site — registering, booking a hotel — finishing there does not complete the task. The person has to come back to the portal and mark it done. Tell them that in the description.
</Warning>

## Create a task

<Steps>
<Step title="Open the Tasks library">
Go to **Program → Portals → Tasks** and click **Add → Add Task**. The tabs — **All Tasks**, **Contact Tasks**, **Group Tasks**, **Submission Tasks** — filter the library by who the task is for.

![The Tasks library under Portals, with Add Task and the type tabs](/images/kb/portal-tasks-library.png)
</Step>
<Step title="Name it in the speaker's words">
**Task Name** is what the portal shows. "Confirm your travel dates" reads better than "Travel confirmation".

![The Add Task panel: Task Name, Type, Description and Task Link](/images/kb/portal-task-add.png)
</Step>
<Step title="Pick the type">
**Type** decides what the task attaches to:

| Type | Who completes it |
| --- | --- |
| **Contacts** | One person — speakers, moderators, chairs, submitters, and individual sponsor or exhibitor contacts. |
| **Groups** | A sponsor or exhibitor company. The task lands on the company and anyone on their team can complete it. |
| **Submissions** | Each session rather than each person — right for "upload your slides". |
</Step>
<Step title="Describe it, and link it">
**Description** tells them what done looks like. **Enter Description** shows the same text to everyone; **Use Field** pulls a contact or session field instead, so each person sees their own value.

**Task Link** works the same way: **Enter Task URL** for one link for all, or **Use Field** to send each person to their own — a personal registration link, say. Links need the `https://` prefix.

Click **Create Task**. The task is in the library, but nobody sees it until it is on a portal.
</Step>
</Steps>

## Assign the task to a portal

A task can sit on as many portals as you like, and each portal can give it its own alias, due date and required flag.

<Steps>
<Step title="Open the portal's Assign Items step">
On **Program → Portals**, open the **⋯** menu on the portal card and choose **Edit Tasks**. That opens the portal editor on its **Assign Items** step.

![The portal card menu with Edit Tasks](/images/kb/portals-card-menu.png)
</Step>
<Step title="Add the task">
In the **Tasks** section click **Add**, tick the task, and click **Add Selected**. It appears in the table with its **Name**, **Alias**, **Due Date**, **Extended Due Date** and **Required** columns.

![The Assign Items step with a Tasks section](/images/kb/portal-editor-assign-items.png)
</Step>
<Step title="Set its settings for this portal">
Click the pencil under **Actions** to open **Edit Settings**:

![Edit Settings for a task on a portal](/images/kb/portal-item-settings.png)

| Setting | What it does |
| --- | --- |
| **Alias** | A different name for the task on this portal only. |
| **Due Date** | A real deadline shared by everyone on this portal. Once it passes, portal users can no longer mark the task complete — they see a message naming the date instead. |
| **Due date relative to assignment** | Instead of one shared date, stamp a personal due date on each person. Choose **When the person is assigned** or **When the assignment email is sent**, then how many days after that. Dates already set on a person are left alone, so changing N later does not rewrite existing deadlines. Preview and send-test emails do not stamp dates. |
| **Extended Due Date** | A grace period after the due date during which the task can still be completed. Set it before the deadline passes. |
| **Required** | Marks the task as required on the portal. The same toggle sits in the table's **Required** column. |
| **Make Completed Tasks View-Only** | Locks a task once it is complete, so nobody can flip it back to incomplete. |
| **Assign By Filter** *(Submissions tasks only)* | Show the task only on submissions that match **Submission Filters** — for example *Format is Breakout*, so keynote speakers never see "upload your slides". **Participant Roles** limits it to particular roles on those submissions. |

Click **Update**.
</Step>
</Steps>

<Tip>
The order tasks appear in is set once per portal, in the **Portal Tasks order** section of the same step: **Smart (recommended)**, **Due date**, or **Custom** drag-and-drop. See [Portals 101](/portals/portals-101#assign-items).
</Tip>

<Warning>
A due date applies whether the task reached someone through the portal's filters or was assigned to them individually, and it applies to forms and file requests too. Tasks already complete can still be reopened.
</Warning>

## See who has done it

Tracking is a column. In **Contacts** (or **Speakers**, **Sponsors**, **Exhibitors**), open **Columns** and add the task; it joins the table, and each row shows where that person is. Save the view so it is there tomorrow — see [Dashboard views](/reporting/dashboard-views).

![A task column in the contacts table](/images/kb/contacts-task-column.png)

| Icon | Status | Meaning |
| --- | --- | --- |
| Green check | **Complete** | Done. |
| Blue circle | **Assigned Via Portal** | Reached them through a portal; still open. Cannot be unassigned from the record — remove it from the portal instead. |
| Amber clipboard | **Manually Assigned** | Assigned to this record directly; still open. Click it to open **Options** or **Unassign Task**. |
| Grey plus | **Not Assigned** | Click to assign it to this one record. |

File requests use the same column with two more states: a yellow clock for **Pending Approval** and red for **Rejected**. To assign to a handful of people without another portal, see [Assign tasks to contacts and groups](/portals/task-assignment).
