Session files are the presentations, handouts and other materials attached to a session. Speakers upload them from the portal once you turn uploads on; admins can upload from the session at any time. Every file keeps its versions, can carry a comment thread, and the whole set downloads as one zip.

This page is about the **Files** tab on a session. File questions on a submission form — including Headshot — are separate: they use **Customize Question → Maximum file size** (up to 5 GB) and do not inherit the settings below. See [Session submission forms](/sessions/submission-forms).

## Why use it

Session files keep the deck, the poster and the handout on the session they belong to, versioned, instead of in an inbox. Tell Sessionboard which files you want from which sessions and by when — one request for everyone, or an [upload slot](#upload-slots) per file — and each speaker sees exactly that in their portal, with the wrong file type refused and a closed deadline explained. On your side, [Slot coverage](#who-still-owes-what-slot-coverage) shows who still owes each file, reminders go out on their own, and the whole set downloads as one zip grouped by session, type or slot for the AV team.

## Enabling files

Uploads are off until you turn them on. Go to **Program → Settings → Files**.

![The Upload Settings card on Program Settings → Files with Enable File Upload and Enable Comments on and Enable participant assignment off](/images/kb/program-settings-files.png)

| Setting | What it does |
| --- | --- |
| **Enable File Upload** | Lets speakers with portal access upload files to their sessions. Off, the session's Files tab tells admins "Speaker file uploads are turned off for this event" and only admins can add files. |
| **Enable Comments** | Turns on the comment thread under each file. |
| **Enable participant assignment** | Requires whoever uploads — admin or portal user — to pick which session participant the file belongs to. |
| **File Size Limits** | **Enable Size Limits**, then a **Size Unit** (KB, MB or GB) with a **Minimum Size** and **Maximum Size**. Without a limit, files can be up to 5 GB each. |

Below Upload Settings, **File Requests** decides *what* speakers are asked for. There are two ways to run it, chosen with the **Use upload slots** switch.

### One file request for every session

With **Use upload slots** off, every session shares a single due date and file-type list:

![The File Requests card with Use upload slots off, showing the single File Due Date, File Limit and Allowed File Types](/images/kb/program-settings-file-requests-off.png)

| Setting | What it does |
| --- | --- |
| **File Due Date** | The deadline shown to speakers in the portal. |
| **File Limit** | Maximum number of files per session, or leave empty for no limit. The limit counts files, not versions — a speaker at the limit can still upload a new version of an existing file, only brand-new files are blocked. Admins are never subject to it. |
| **Allowed File Types** | **All**, or any mix of PDF, PPT, Image, Video, Audio, Word, Excel, ZIP, PNG, JPEG, GIF, SVG and MP4. |

Events created before October 2026 start here, and nothing about them changes until you turn the switch on.

### Upload slots

Turn **Use upload slots** on when you need to ask for *specific* files — a poster, a presentation, a handout — each with its own due date, accepted types and set of sessions. Poster galleries need this: a gallery collects from a **Poster** slot. New events, and events you clone, have it on already.

![The File Requests card with Use upload slots on, and the Upload slots list beneath it — a Poster slot and a Presentation slot, each showing its due date, file types, file limit and filters, with Add slot and Show archived](/images/kb/program-settings-files-upload-slots.png)

The moment you turn it on, your current due date, file limit and file types become the first slot, so speakers are asked for exactly what they were before. Then **Add slot** for each further file you want, or open a slot to change it:

![The Edit upload slot panel — Name, File kind, Instructions for speakers, Due date and Extended deadline, Accept late uploads, Accepted file types, Minimum and Maximum files, Required, Reminders with 7 days and 1 day before chips, Only some sessions with Session filters and a sessions-match count, and Who can upload](/images/kb/content-slot-editor.png)

| Field | What it does |
| --- | --- |
| **Name** and **File kind** | The name speakers see, and what the file is — **Presentation**, **Poster**, **Handout**, **Abstract** or **Other**. The kind is what poster galleries and the Poster Builder read, so a poster ask must be of kind Poster whatever you call it. |
| **Instructions for speakers** | Shown above the drop zone in the portal. |
| **Due date**, **Extended deadline**, **Accept late uploads** | The deadline speakers see; an optional later date the drop zone stays open until; or no cut-off at all. Leave the due date empty for no deadline. |
| **Accepted file types** | Only the ticked types are accepted, enforced on upload: PDF, PowerPoint, Word, Excel, Image, PNG, JPEG, GIF, SVG, Video, MP4, Audio, ZIP, CSV and Text. Tick nothing to accept any file type. |
| **Minimum files** and **Maximum files** | How many files the slot takes per session. Leave the maximum empty for no limit. |
| **Required** | Counts the slot as missing in coverage and reminders until a file is uploaded. |
| **Only some sessions** | Off, every session owes this file. On, add **Session filters** — any session field, such as **Format is Poster** — and the panel counts how many sessions match. |
| **Who can upload** | Leave on **Any participant**, or restrict the slot to particular session roles. |
| **Reminders** | Days before the due date (or the extended deadline, if set) to email speakers who still owe the file — up to five, from 0 to 30 days, **7** and **1** by default. One overdue notice goes out on its own after the deadline passes. Reminders only go to participants with portal access whose role the slot allows, and only for sessions the slot applies to that have nothing in it yet. |

Drag the handle on a slot row to change the order speakers see them in (or focus the handle and use **Space**, the arrow keys, and **Space** again). **Archive slot** hides a slot from speakers; files already uploaded to it stay attached to their sessions. **Show archived** lists retired slots and lets you **Restore slot**.

Select **Save Changes**. In the portal, each session's **Files** tab then shows one card per slot that applies to it — the slot's name, instructions, due date, accepted types and how many files it still takes — with its own drop zone. A speaker cannot put a Word file in a PDF-only slot, cannot upload to a slot whose deadline has passed (unless you set an extended deadline or **Accept late uploads**), and once a slot is full can only upload a new version of a file already in it. What that looks like from their side is in [Upload files & make comments](/participants/upload-files).

<Note>
Deadlines hold speakers, not your team. Admins uploading from a session's Files tab can always add a file to a slot, whatever its due date. Turning **Use upload slots** off again brings back the single File Due Date, File Limit and Allowed File Types, filled in from the slots; files keep the slot they were uploaded to, so nothing is lost if you turn it back on.
</Note>

<Tip>
Create a [portal task](/portals/assign-tasks) called "Upload your presentation" with the due date and a link to that participant article, so the upload shows up on every speaker's to-do list.
</Tip>

## Uploading files as an admin

Open the session (select **Edit** on its row) and choose the **Files** tab. Drag files onto the drop zone or select it to browse; the panel shows how many more files the session can take. To replace an existing file rather than add one, choose it under **New version of:** before uploading — the earlier version stays in the file's history.

![The Files tab on a session — the Upload Files drop zone above Session Files, where each file shows its latest version, upload date and size, uploader, comments and type badge](/images/kb/session-files-tab.png)

Each file shows its **Latest Version**, upload date, size, who uploaded it and its type. **Show History** lists earlier versions; the ⋯ menu offers **Download File**, **Copy link**, **Edit File Type** and **Delete File**.

![The file menu: Download File, Copy link, Edit File Type, Delete File](/images/kb/session-file-menu.png)

### With upload slots

When the event uses [upload slots](#upload-slots), the Files tab is grouped by slot. Each slot the session owes gets its own heading with its due date, **Required** badge and file count, so you can see at a glance that the presentation is in but the handout is not; slots whose filters do not match the session are left out. Files that are not attached to any slot sit under **Other files**.

![The Files tab on a podium session grouped by slot — Presentation with one file, and Handout with "No files in this slot"](/images/kb/session-files-slot-groups.png)

Uploading as an admin, pick the **Slot** for each staged file before confirming. In the ⋯ menu, **Edit File Type** becomes **Move to slot**: choose a slot (or **No slot**) and the file, with all its versions and comments, moves there and takes the slot's file kind. Only slots that apply to the session are offered, so you cannot file a podium session's deck under Poster by mistake.

![The Move to slot panel on a file, with the Slot select open showing No slot, Presentation and Handout](/images/kb/session-file-move-to-slot.png)

## Viewing submitted files

Two places show everything that has come in:

- **Program → Submissions → Files** lists every file in the event with the session it belongs to, the uploader and the upload date, in a grid or a list. Search, sort by upload date, and filter by **Upload date** or **File type**. Selecting a file opens it.
- **Program → Submissions → Sessions** — add the **Files** column under **Columns** to see which sessions have files and how many (versions are not counted). Open a session's **Files** tab to see them.

![Submission Files: a grid of every uploaded file with its session, uploader and upload date, plus Select all, search, sort and filters](/images/kb/submission-files-module.png)

### Who still owes what: slot coverage

With upload slots on, **Program → Submissions → Files** gains a second view, **Slot coverage**, that answers the question the file list cannot: for each slot, which sessions have uploaded, which are still missing, and which are overdue.

![The Slot coverage view — a card per slot (Poster, Presentation, Handout) with uploaded, missing and overdue counts and a progress bar, Status, Format, Track and Session date filters, and a table of one row per session and slot with status badges and Export CSV and Download files buttons](/images/kb/files-slot-coverage.png)

- The cards at the top count the sessions each slot applies to — a Poster slot filtered to **Format is Poster** counts only poster sessions. Select a card to limit the table to that slot; select it again to clear.
- Filter the table by **Status** (Missing, Uploaded, Overdue), **Format**, **Track** or **Session date**. The filters live in the page URL, so a filtered view can be bookmarked or sent to a colleague.
- **Export CSV** downloads the rows you are looking at. **Download files** opens the [zip download](#downloading-files-as-a-zip) already scoped to the selected slot.
- A session's row opens that session, so chasing a missing file is one click away.

The sessions grid gets the same answer as columns. Under **Columns** on **Program → Submissions → Sessions**, each active slot offers **Files: *slot*** — **Uploaded**, **Missing** or **Overdue**, blank when the slot does not apply to the session — and **Files: *slot* (count)**. Filter and sort on them like any other column, for example *Files: Poster is Overdue* to email the stragglers.

![The Columns panel on the sessions grid listing a Files column for Poster, a Poster count column, and Files columns for Presentation and Handout alongside the other columns](/images/kb/sessions-columns-slot-files.png)

The same fields are available to reports as `content_slots.<slot>.status` and `.count`; note that in reports every session is counted, whatever the slot's session filters say.

## File comments

With **Enable Comments** on, every file has a thread that session speakers and admins share. Select **Show Comments** under a file (or **Expand All** to open every thread) to read it and add a comment; each entry records who wrote it and when.

<Warning>
Nobody is emailed when a comment is added — not the admin, not the speaker. If you leave feedback a speaker needs to act on, [send them an email](/communications/create-send-emails) pointing them at the portal.
</Warning>

## Sharing a single file

**Copy link** (on the file row or in its ⋯ menu) puts a direct link to the current version on your clipboard, so a colleague can open the file without downloading it or signing in to the session.

## Downloading files as a zip

The latest version of each selected file is bundled into a zip and emailed to you. Start from either place:

- **Program → Submissions → Files**: select the files (or **Select all**), then **Download Files**.
- **Program → Submissions → Sessions**: select the sessions, then **Download Files** in the bar above the table.

![The Download Files panel: "Download 9 files for 9 selected sessions", Group files by Content Type, Session Date, Room, Session, and the folder tree those groupings produce](/images/kb/files-download-sidebar.png)

**Group files by** decides the folder structure inside the zip. Select **Edit** to choose and order any of **Content Type**, **Session Date**, **Room** and **Session**; the tree underneath previews the folders, and you can expand it and untick anything you do not want included. Select **Generate Download**. The zip is built in the background — up to ten minutes for a large set — and an email with the subject **Your file is ready** brings the download link.

<Note>
Only the latest version of each file goes into the zip. To keep an earlier version, open the file's history on the session and download it from there.
</Note>

Generated [title slides](/marketing/slides#attached-slides) are exported too. Under **Content Type** they land in a folder called **Title slides**, and when you group by **Session** each session folder gets its own **Title slides** subfolder beside the speaker's uploads, so the production team finds every room's opener in one place. Superseded slide versions are left out.

### Downloading one slot

With upload slots on, the **Download Files** wizard (⋯ → **Download files bundle...** on **Program → Submissions → Sessions**) gives its **Session files** source an **Upload slot** select — leave it on **All slots**, or pick one to download, say, every poster and nothing else. **By upload slot** joins the grouping options, putting each slot's files in a folder of its own with **No upload slot** for the rest. The **Download files** button on the [Slot coverage](#who-still-owes-what-slot-coverage) view opens the same wizard with the slot already chosen.

![The download wizard's Session files step with the Upload slot select set to Poster](/images/kb/files-download-upload-slot.png)

Both download buttons need the **Export** permission on Sessions; without it the button is disabled.

### When a zip says Incomplete

Every export is listed under **History → Exports**. An **Incomplete** label there means the zip may be missing files. What to do depends on which download made it:

- **Download files bundle...** (the wizard): "Incomplete — N files could not be included" means those files failed. Open **manifest.csv** inside the zip; it lists every file and marks the failed ones with the reason. Export just those sessions or that slot again. A bundle holds up to 25,000 files, and "hit the file limit" means you passed it, so export by track, day or upload slot instead.
- **Download Files** (the panel on Files or Sessions): "Incomplete — this zip has X of Y selected" compares the size of the zip with the recorded size of the files you picked. Zips are compressed, so a gap of about a tenth with every file present is normal. If files are missing, run a new export with a smaller selection.
