<IfFeature id="approvals">

With approvals on, a new session file, or a new version of one, starts as **Pending**. It goes only to the reviewers you choose, one step after another, and reaches integrations, embeds and poster galleries once the last step approves it. Every decision is kept in the file's history.

<Note>
Approvals is an Early Access **Beta**. Request it per event from [Early Access](/get-started/early-access) and our team will switch it on for you. Once it is on, **Publish → Approvals** appears in the event sidebar and **Program → Settings → Files** gains the approval setting.
</Note>

## Why use it

Decks and posters often need a sign-off before they go anywhere public: a track chair checks the content, compliance checks a sponsored session, the AV team checks the format. Approvals puts that sign-off on the file itself, instead of an email thread. Reviewers get an email and an in-app notification when a file is waiting on them, everyone can see who still needs to review, and nothing unapproved leaves Sessionboard by accident.

## What changes when you turn it on

- **Only new files are held.** Files uploaded before you turn approval on stay exactly as they are and keep flowing to integrations. Nothing is re-reviewed after the fact.
- **Pending and denied files are held back.** They are not sent to integrations, embeds, poster galleries, or to Public API consumers that ask for approved files. Admins still see them on the session and in **Program → Submissions → Files**.
- **The approved version stays live during review.** When a speaker uploads a new version of an approved file, the approved version keeps being used until the new one is approved.

## Set up the workflow

<Steps>

<Step title="Turn on approval for session files">

Go to **Program → Settings → Files** and switch on **Require approval for session files**. The first time, this opens the workflow builder. Afterwards, use **Edit approval workflow**.

</Step>

<Step title="Choose which files need approval">

**Applies to** is every new session file by default. **Limit to some files** narrows it with conditions, for example only files in the Poster upload slot, or only files uploaded by speakers.

</Step>

<Step title="Add steps">

Steps run one after another. Reviewers inside a step work in parallel. For each step:

| Setting | What it does |
| --- | --- |
| **Only run this step when…** | Optional conditions. A step whose conditions don't match the file is skipped and recorded in the history. |
| **Who reviews** | People or roles from your event team. Add a **Route to** rule to send matching files to different reviewers, for example the Retail track to its chair. The first matching rule wins, and files that match no rule go to the step's default reviewers. A route can have a label that reviewers see. |
| **Approval needed from** | **Any one** reviewer, **Everyone**, or **At least N**. |
| **Due within (hours)** | How long reviewers have for this step. |

</Step>

<Step title="Set new versions and reminders">

**On a new version, restart from** decides whether a replaced file goes back to **The first step** or **The step it was on**. **Automatic reminders** nudges reviewers who haven't decided every so many hours, up to the number of times you set. Leave it empty for no automatic reminders.

</Step>

<Step title="Test the routing">

Pick an existing file in the test panel to see which steps would run for it and who would review each one, before you save.

</Step>

</Steps>

Conditions can check the file's **File type**, **Upload slot**, **File format** (PDF, Office document, image, video, audio), and **Uploaded by** (speaker or participant, event team, or API / integration), and the session's **Track**, **Format**, **Level** and **Sponsor tier**.

Reviewers must be active members of the event team, so everyone you assign can open the review. Saving changes while files are mid-review doesn't re-route them: the new steps and reviewers apply from their next step.

## Review files

**Publish → Approvals** lists every file in the workflow, with tabs for **Waiting on me**, **Pending**, **Approved** and **Denied**. Each row shows the session, the current step, and the avatars of the reviewers it is still waiting on.

**Review** opens the file with a preview (**Full screen** for decks and posters), the steps it has passed and the ones still to come, who has decided at each step, and its full history.

- **Approve** completes your part of the step. When the step's rule is met, the next step starts. After the last step, the file is approved.
- **Deny** asks for changes. A note is required, and it is sent to the person who uploaded the file. The remaining reviewers don't need to act.
- **Remind** emails the reviewers who haven't decided yet. Each reviewer can be reminded once every 4 hours.

Select several rows to approve, deny or remind in bulk. Files you can't decide are skipped. Event team members whose role is limited to some sessions see only the files on those sessions, plus any file they have been asked to review.

### Override a decision

Admins who can edit session files can **Override** from the review: **Approve now** skips any remaining steps, **Deny now** sends the file back with a note, and **Revert to pending** restarts the workflow. Overrides are recorded in the history as overrides.

## On the Files list

**Program → Submissions → Files** shows each file's approval status, filters by **Pending**, **Approved**, **Denied** or **Waiting on me**, and shows the session's room and time and who last changed the file. The session's **Files** tab shows the same status on each file.

## What speakers see

In the portal, speakers see **Pending review**, **Approved** or **Changes requested** on each file they uploaded, never the steps or the reviewers. When a file is denied they see your note, with **Upload new version** to send it back for review. The new version starts the workflow again from the step you chose.

## Notifications

| When | Who | How |
| --- | --- | --- |
| A step starts, or a reviewer is added | Each reviewer on that step | Email and in-app |
| A reminder is sent, by hand or automatically | Reviewers who haven't decided | Email and in-app |
| The last step approves the file | The person who uploaded it | Email and in-app |
| A reviewer denies the file | The person who uploaded it | Email and in-app, with the note |

The emails are listed under System Notifications, in the Files & Exports category, where you can edit their wording.

## Turning it off

Switching off **Require approval for session files** stops holding new files. Files that are mid-review keep their status until someone decides them. If the Approvals Beta is switched off for the event, nothing is held back any more, and every file is treated as it was before approvals.
