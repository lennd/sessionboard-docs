A webhook sends an HTTP request from Sessionboard to a URL you choose each time something changes, such as a session being updated or a contact being added. Your system hears about the change straight away instead of asking the API over and over.

## Why use it

- Keep a CRM, marketing tool or website in step with your program without scheduled exports or polling.
- Trigger your own automations, for example notifying a team channel when a session is created.
- Every request is signed, so your receiver can confirm it came from Sessionboard.

## Where to set up webhooks

- **One event:** open the event and go to **Settings › Integrations › Webhooks**. Endpoints here receive changes in that event only.
- **Every event in the organization:** go to **Organization Settings › Webhooks**. Endpoints here receive changes in all of the organization's events, plus organization-level changes such as new contacts.

## Add an endpoint

1. Click **Add endpoint** and enter the URL that should receive the requests. It must be a public `https` address.
2. Choose the event types to send, such as `session.updated` or `contact.created`. Leave them all clear to receive every event type, including ones added later. Events with Registration turned on also send **Registrations** (`registration.created`, `registration.confirmed`, `registration.updated`, `registration.waitlisted`, `registration.declined`, `registration.canceled`, `registration.transferred`, `registration.checked_in`) and **Orders** (`order.paid`, `order.refunded`). Each carries the registration or order id; fetch the record from `metadata.resource_url` with an API token that has `read:registrations`.
   A session's `session.updated` also covers its people: adding or removing a speaker or other participant (which also sends `session.speaker.attached` or `session.speaker.detached`), and a speaker confirming, declining or withdrawing in the portal. A session created with speakers, for example by **Import Sessions**, lists them under `session_speakers` in `session.created`.
3. Add custom headers if your receiver expects them, for example an API key.
4. Save, then copy the endpoint's **signing secret** and give it to whoever runs the receiver. They use it to verify each request.

<Note>
Webhook requests are sent in real time and are **not** subject to the API's 3-minute cache.
</Note>

## Check that it works

- **Testing** sends an example of any event type to the endpoint, so you can confirm your receiver accepts it.
- **Logs** lists every delivery with its status and response, and lets you resend a message.
- Failed deliveries are retried automatically over about a day. An endpoint that keeps failing for several days is turned off; turn it back on once the receiver is fixed.

<Tip>
For the payload format, the full list of event types, and how to verify signatures in code, see the [developer documentation](https://apidocs.sessionboard.com/webhooks).
</Tip>
