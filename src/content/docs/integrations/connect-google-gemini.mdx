Google Gemini can connect to Sessionboard's MCP server three ways, depending on which Gemini you use: the **Gemini app** (custom connected apps), **Gemini Enterprise** (admin-configured connectors), or the **Gemini CLI** (developer tool). All three talk to the same server and use your Sessionboard sign-in.

<Note>
This page covers the Gemini-specific setup. For prerequisites (AI features, the AI Access permission), example prompts, and privacy details, see [Connect Claude and ChatGPT to Sessionboard](/integrations/connect-ai-assistants) — everything there except the client steps applies to Gemini too. The full tool list lives in the [MCP Server reference](https://apidocs.sessionboard.com/insights/mcp-server).
</Note>

## Pick the server URL for your region

| Your admin login URL | Region | MCP server URL |
|----|----|----|
| `appv2.sessionboard.com` | United States | `https://mcp.sessionboard.com/mcp` |
| `appv2-eu.sessionboard.com` | Europe | `https://mcp-eu.sessionboard.com/mcp` |
| `appv2-me.sessionboard.com` | Middle East | `https://mcp-me.sessionboard.com/mcp` |

## Option 1 — Gemini app (custom connected apps)

Google is rolling out custom MCP apps in the Gemini web app under **Connected Apps**. Eligibility is limited while it rolls out — currently personal Google Accounts (not work/school), US, English, 18+, with Gemini Spark access and **Keep Activity** turned on. Details: [Google's help article](https://support.google.com/gemini/answer/17209137).

<Steps>
  <Step title="Open Connected Apps settings">
    In the Gemini web app, open **Settings → Connected Apps** and find **Custom apps** (shown for eligible accounts).
  </Step>
  <Step title="Add the Sessionboard server">
    Paste the MCP server URL for your region — for example `https://mcp.sessionboard.com/mcp` — as the custom app link. Sessionboard supports dynamic client registration, so no client credentials are needed.
  </Step>
  <Step title="Sign in and authorize">
    Gemini opens the Sessionboard OAuth flow. Sign in with your Sessionboard admin credentials, pick your organization on the consent screen, and click **Authorize**. Once connected in the web app, the connector also works in the Gemini mobile app.
  </Step>
  <Step title="Use it in a chat">
    Ask something like *"What events do we have in Sessionboard?"*. Gemini asks for manual confirmation before any write action.
  </Step>
</Steps>

## Option 2 — Gemini Enterprise (admin setup)

A Gemini Enterprise administrator can add Sessionboard as a **Custom MCP Server** connector so every licensed user in the workspace gets it. Follow [Google's setup guide](https://docs.cloud.google.com/gemini/enterprise/docs/connectors/custom-mcp-server/set-up-custom-mcp-server) with these values:

| Field | Value (US region) |
|----|----|
| MCP Server URL | `https://mcp.sessionboard.com/mcp` |
| Authorization URL | `https://public-api.sessionboard.com/oauth/authorize` |
| Token URL | `https://public-api.sessionboard.com/oauth/token` |

For EU or Middle East organizations, swap in `mcp-eu` / `public-api-eu` or `mcp-me` / `public-api-me` respectively. Sessionboard's MCP server uses the **streamable HTTP** transport Gemini Enterprise requires.

<Note>
Gemini Enterprise's setup form asks for an OAuth **client ID and secret**. Sessionboard's OAuth server currently issues clients through dynamic client registration (used automatically by Claude, ChatGPT, Copilot Studio, and the Gemini CLI) and does not yet provide client secrets for manual setup. If you're rolling out Gemini Enterprise, contact [support@sessionboard.com](mailto:support@sessionboard.com) and we'll work through the configuration with you.
</Note>

## Option 3 — Gemini CLI (developers)

The [Gemini CLI](https://github.com/google-gemini/gemini-cli) supports remote MCP servers with automatic OAuth discovery. Add this to your `~/.gemini/settings.json`:

```json
{
  "mcpServers": {
    "sessionboard": {
      "httpUrl": "https://mcp.sessionboard.com/mcp"
    }
  }
}
```

On first use the CLI detects that the server requires OAuth, discovers Sessionboard's sign-in endpoints, registers itself automatically, and opens your browser to complete the Sessionboard sign-in and consent. Swap in your region's URL if your organization is hosted in the EU or Middle East.

## Troubleshooting

| Symptom | Likely cause |
|----|----|
| "Custom apps" missing in the Gemini app | Your account isn't in the rollout yet (work/school account, region, or Keep Activity off) — see Google's eligibility list above |
| Consent screen shows no organizations | Wrong regional URL, AI features not enabled for your org, or your user lacks the AI Access permission — see [Prerequisites](/integrations/connect-ai-assistants#prerequisites) |
| Gemini Enterprise setup asks for a client secret | Manual client credentials aren't offered yet — contact [support@sessionboard.com](mailto:support@sessionboard.com) |
| CLI hangs on first call | The OAuth browser window is waiting for sign-in; complete it or re-run `gemini` |
