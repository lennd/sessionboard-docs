## What you can do with an API token
API tokens let you:

- Sync your event data with external systems (CRMs, BI tools, custom dashboards)
- Build custom integrations using the [Sessionboard Public API](https://apidocs.sessionboard.com/introduction)
- Connect AI assistants (Claude, ChatGPT, and other Model Context Protocol–compatible clients) to your Sessionboard organization so they can query and act on your event data in natural language
- Run scheduled or programmatic reports through SbQL

<Tip>
**💡TIP- Before you start**

- **Tokens are generated at the organization level**, not per event. Each token has access scoped to your org. You must be an organization administrator to generate, edit, or revoke tokens.
- **Tokens are sensitive.** Treat them like passwords — never share them in public channels, never commit them to source control, and store them in a secrets manager or environment variable.
</Tip>

## Where to find your Event ID and Organization ID

Developers and integration partners ask for these alongside the token. Neither is secret, and neither is displayed on the API Tokens page — they are in the address bar.

- **Event ID** — the number after `/event/` while you are inside the event: `app.sessionboard.com/event/`**`12345`**`/sessions`. It never changes, and it is the `{eventId}` in every event endpoint of the public API.
- **Organization ID** — the long identifier after `/org/` while you are in Organization Settings: `app.sessionboard.com/org/`**`a1b2c3d4-…`**`/settings/api-tokens`. It is the `{orgId}` in the organization endpoints.

A developer who already has a token can also list every event it can see, with its `id` and `name`, by calling `GET /v1/events`. For the full pre-connection checklist — order of operations, field mapping and reading the sync history — see [Before you connect](/integrations/integration-readiness).

## How to generate an API token
### 1. Open Organization Settings
Log in to the Sessionboard admin dashboard and click **Organization Settings** in the sidebar.

### 2. Go to API Tokens
In the Organization Settings menu, select the **API Tokens** section.

![In the Organization Settings menu, select the API Tokens section](/images/kb/d6a38e5b-image-png-May-05-2026-07-54-14-1264-PM.png)

### 3. Create a new token
Click **Create Token**. You'll be asked for:

- **A descriptive name** *(optional)*: e.g. "Tableau dashboard." This helps you identify the token later when reviewing or revoking it.
- **Permissions:** see the next section.
- **PII Obfuscation:** recommended. See the dedicated section below.
- **Event restrictions** *(optional)*: limit the token to specific events instead of your whole organization.

![Event restrictions (optional)](/images/kb/31d4c602-image-png-May-05-2026-07-53-04-0808-PM.png)

### 4. Choose token scopes
API tokens use scopes to control what the token can read or write. Every scope is its own checkbox — read scopes included — so grant only what your integration actually needs.

| Read scope | What it does |
|----|----|
| **read:events** | Event data. |
| **read:sessions** | Session data. |
| **read:contacts** | Speaker and contact data. |
| **read:reports** | Saved reports. |
| **read:dashboards** | Dashboards. |
| **read:insights** | AI-powered insights and SbQL queries. Required for any MCP / AI assistant connection. |
| **read:transcriptions** | Session transcriptions and recordings — the `/transcriptions`, `/content` and `/content/documents` routes that expose live transcripts, recaps and event reports. |
| **read:media** | Uploaded media items and their transcription status. |

| Write scope | What it does |
|----|----|
| **write:events** | Create, update and delete dashboards, reports, agenda drafts, rules and personas. |
| **write:sessions** | Create, update, delete and restore sessions. |
| **write:contacts** | Create, update, delete and restore contacts. |
| **write:exhibitors / write:sponsors** | Create, update, delete and restore exhibitor and sponsor records. |
| **write:fields** | Create, update and delete custom fields. |
| **write:metadata** | Rooms, tracks, tags, formats, levels, languages and statuses. |
| **write:transcriptions** | Create, update and delete session transcriptions and recordings. |
| **write:media** | Upload media files for automatic transcription. |

![Selecting scopes while generating an API token](/images/kb/b43c840d-image-png-May-05-2026-07-55-14-8716-PM.png)

For your security team's SIEM, check **Audit log export** (`read:audit_logs`) instead. It replaces every other scope and creates a token that only reads your organization's logs — see [Export audit logs to a SIEM](/integrations/siem-log-export).

<Note>
**📌 Note:** If you don't know which scopes you need, start with the read scopes for the records you use and add write scopes only when you have a clear use case for them.
</Note>

### 5. PII Obfuscation (recommended for AI and third-party integrations)
Sessionboard includes a **PII Obfuscation** switch that redacts personal contact data (emails, phone numbers, names) from AI and Insights/SbQL query results returned to the token.

- **Enabled (recommended for AI assistants and third-party integrations):** Email addresses are returned as `j***@a***.com`, phone numbers as `***-***-4567`, and similar masking applies to other personal fields in query results.
- **Disabled (default):** Full PII is returned.

Note that connections made through the OAuth flow (Claude, ChatGPT, and other [AI assistant connections](/integrations/connect-ai-assistants)) always mask PII in query results regardless of any token setting.

![Disabled: Full PII is returned in API responses](/images/kb/211f0e53-image-png-May-05-2026-07-58-28-2747-PM.png)

<Warning>
We **strongly recommend turning PII Obfuscation on** for tokens used by AI assistants or any third-party integration. It protects your speakers' and contacts' personal information from being exposed in logs, AI conversation histories, or downstream systems.

You can set PII Obfuscation per token, so different integrations can have different obfuscation rules depending on what they need to do.
</Warning>

### 6. Copy the token immediately
<Note>
🔒 **Note: copy your token now.** When you click **Generate**, the full token value is displayed **only once**. After you close the dialog, the full token is hidden for security and cannot be retrieved again. Copy it immediately and store it in a secure location (a password manager, secrets vault, or environment variable). If you lose it, you'll need to generate a new one.
</Note>

This is intentional behavior, we never store the full token in a way that can be displayed back to you, so even Sessionboard staff can't recover it for you.

### Using your token
Include the token in the `x-access-token` header on every API request. Example:

bash

    curl -X GET https://public-api.sessionboard.com/v1/events
      -H "x-access-token: YOUR_TOKEN"

Use `https://public-api.sessionboard.com` for US-hosted organizations, `https://public-api-eu.sessionboard.com` for EU-hosted organizations, and `https://public-api-me.sessionboard.com` for Middle East–hosted organizations.

<Note>
**💡TIP-** For full endpoint documentation, request and response schemas, and code samples in JavaScript and Python, see the [API Reference](https://apidocs.sessionboard.com/api-reference/overview).
</Note>

### Where to find your Event ID and Organization ID

Integration partners and your own developers often ask for two numbers alongside the token. Both are in the address bar:

- **Event ID** — open the event and read the number after `/event/` in the URL, for example `…sessionboard.com/event/1234/dashboard` → `1234`. It is the same `id` the API returns from `GET /v1/events`.
- **Organization ID** — on an organization page (the **Events** list, **Organization Settings**) read the number after `/org/`, for example `…sessionboard.com/org/56/events` → `56`.

The token itself is already tied to your organization, so most partners need only the Event ID. Credentials a partner issues — a client ID, secret, or their own event key — come from that partner's admin console, not from Sessionboard; the connector pages under [Apps](/apps/event-platform-comparison) say which ones each integration asks for.

### Connecting AI assistants (Claude, ChatGPT, and other MCP clients)
Sessionboard supports the **Model Context Protocol (MCP)**, an open standard developed by Anthropic that lets AI assistants securely query and act on external data. You can connect Claude Desktop, Claude Code, ChatGPT, or any MCP-compatible client to your Sessionboard organization so the AI can answer questions about your data, build reports, and (with write scopes) make changes on your behalf.

<Tip>
For step-by-step setup guides — [Claude](/integrations/connect-claude), [ChatGPT](/integrations/connect-chatgpt), [Microsoft Copilot](/integrations/connect-microsoft-copilot), and [Google Gemini](/integrations/connect-google-gemini) — including the correct server URL for US, EU, and Middle East regions, start at [Connect AI assistants to Sessionboard](/integrations/connect-ai-assistants).
</Tip>

## How it works
You have two paths to connect:

1. **OAuth (recommended for most clients)** : When you connect an MCP-compatible AI client to Sessionboard, the client walks you through an OAuth authorization flow automatically. You don't need to generate a token manually; the OAuth flow handles authentication for you. This is the easiest path for browser-based clients like Claude Desktop or ChatGPT.
2. **Manual API token:** If your client doesn't support OAuth (or you prefer manual control), generate an API token following the steps above. Make sure to grant the **read:insights** scope — MCP access follows from that scope, there is no separate toggle. Add write scopes (e.g., `write:sessions`) only if you want the AI to make changes.

## Configuring your AI client
For AI clients that accept a remote MCP server URL, point them to:

- **US region:** `https://mcp.sessionboard.com/mcp`
- **EU region:** `https://mcp-eu.sessionboard.com/mcp`
- **Middle East region:** `https://mcp-me.sessionboard.com/mcp`

<Tip>
The MCP server exposes 38 tools covering search, read, and write operations. You can ask the AI things like *"How many sessions are accepted for our 2026 conference?"*, *"Show me the top 10 speakers by session count,"* or *"Create a new track called 'AI & Machine Learning.'"*
</Tip>

## Prerequisites for MCP access
Before MCP requests will succeed, three things must be true on your account:

1. AI features must be enabled for your organization. Contact Sessionboard support or your account manager if you're not sure.
2. MCP access must be enabled on your organization (a separate feature flag).
3. MCP must be enabled on the API token, with the **read:insights** scope (and any write scopes you need).

If any of these are missing, MCP requests will return a `403 Forbidden` error.

<Note>
For full MCP details: available tools, prompt templates, security model, and example conversations ,see the [MCP Server documentation](https://apidocs.sessionboard.com/insights/mcp-server).
</Note>

## Security and best practices
- **Turn on PII Obfuscation.** Enable the PII Obfuscation switch unless your integration has a specific need for full personal data.
- **Scope tokens narrowly.** Generate separate tokens for separate integrations and grant only the scopes each one actually needs. A read-only Tableau dashboard doesn't need write scopes; a sync job that only updates sessions doesn't need write access to contacts.
- **Restrict to specific events when possible.** If a token only needs access to one event, scope it that way rather than giving it organization-wide access.
- **Rotate tokens periodically** and revoke them as soon as an integration is decommissioned or a team member leaves.
- **Never commit tokens to source control or share them in chat.** If a token is compromised, revoke it immediately from the API Tokens settings page and generate a replacement.
- **Audit log.** All API calls are recorded with source, method, response time, and token ID. Organization administrators can review this log at any time.

## Managing and revoking tokens
From the **Organization Settings → API Tokens** page you can:

- Rename a token
- Edit its scopes, event restrictions, and PII Obfuscation setting
- Revoke a token immediately (any integration using it will stop working)

Revoking a token cannot be undone. If you need to give the same integration access again, generate a new token and update the integration's configuration with the new value.

### Rate limits and caching
The Sessionboard API enforces rate limits to ensure fair usage. Build your integration to handle `429 Too Many Requests` responses with exponential backoff. Some endpoints (individual session retrieval and session search) are cached for 3 minutes, so changes you make in Sessionboard may take up to 3 minutes to appear in API responses. Webhook notifications are not subject to this cache and are delivered in real time.

<Note>
For full details, see [Rate Limiting](https://apidocs.sessionboard.com/rate-limiting).
</Note>
