Sessionboard ships a remote **MCP (Model Context Protocol) server** that lets AI assistants securely query and act on your event data. Claude, ChatGPT, Microsoft Copilot, and Google Gemini all connect the same way: you paste your region's server URL (or install the directory listing), and the assistant opens a Sessionboard sign-in. You pick the organization and choose **Authorize**. That sign-in is OAuth. You do not create an API token, and there is no MCP switch to turn on in Sessionboard.

## Pick the server URL for your region

Your organization's data lives in one region, and each region has its own MCP server. Use the server that matches where you sign in to Sessionboard:

| Your admin login URL | Region | MCP server URL |
|----|----|----|
| `appv2.sessionboard.com` | United States | `https://mcp.sessionboard.com/mcp` |
| `appv2-eu.sessionboard.com` | Europe | `https://mcp-eu.sessionboard.com/mcp` |
| `appv2-me.sessionboard.com` | Middle East | `https://mcp-me.sessionboard.com/mcp` |

<Warning>
The regions are separate deployments — a connector pointed at the US server cannot see an EU or Middle East organization, and vice versa. If your assistant connects but shows no organizations on the consent screen, you're almost certainly on the wrong regional URL.
</Warning>

## Prerequisites

Before the consent screen will list your organization, two things must be true:

1. **AI features are enabled for your organization.** To check, an organization admin opens **API Tokens** in Organization Settings. When AI is off, a banner at the top reads *AI features are disabled for this organization.* No banner means AI is on. If it's off, contact [support@sessionboard.com](mailto:support@sessionboard.com) or your account manager to have it turned on.
2. **Your role includes Connect AI assistants.** Organization administrators have it. Other roles need it granted under your organization's role settings.

The assistant also has to support a remote MCP server with OAuth. Claude, ChatGPT, Copilot Studio, and Gemini do. Plan requirements are noted in each guide.

An API token is a different credential, for scripts and for the public API. It does not sign you in to Claude, ChatGPT, Copilot, or Gemini. See [Generating API tokens](/integrations/api-tokens) when a developer needs one.

## What you can ask

The MCP server exposes 38 tools covering search, natural-language queries (via SbQL), reporting, and — if you authorize them — write operations. Some starting points:

- *"What events do we have in Sessionboard?"*
- *"How many sessions are still pending review for [event name]?"*
- *"Search Sessionboard for keynote sessions"*
- *"Show me the top 10 speakers by session count"*
- *"Create a new session called 'AI in Events' in [event name]"*
- *"Run our speaker-status report and summarize it"*

The complete list of tools, their parameters, and worked example conversations live in the [MCP Server reference](https://apidocs.sessionboard.com/insights/mcp-server).

<Tip>
Write actions (creating or updating sessions, contacts, metadata, and so on) only work if you granted write scopes during authorization, and assistants ask for confirmation before destructive changes.
</Tip>

## Privacy and PII

Two different rules apply, depending on how the assistant reads your data:

- **Natural-language and SbQL query results are always masked on OAuth connections.** When the assistant answers questions through Sessionboard's query engine (most reporting and "how many / show me" prompts), contact email addresses come back as `j***@a***.com`, phone numbers as `***-***-4567`, and similar masking applies to other personal fields. This is enforced server-side for every OAuth connection and can't be turned off.
- **Direct record reads follow your granted scopes.** When the assistant opens a specific record (for example, pulling up one contact's profile), it receives the fields your authorization allows, unmasked. Only connect assistants you trust, and remember that anything the assistant reads can end up in its conversation history.

A script that calls the public API with an API token follows that token's **PII Obfuscation** setting instead. It is **off by default**. Turn it on for any token a third party will use. See [Generating API tokens](/integrations/api-tokens#5-pii-obfuscation-recommended-for-ai-and-third-party-integrations).

## Troubleshooting

| Symptom | Likely cause |
|----|----|
| Consent screen shows no organizations | Wrong regional URL, AI features not enabled for your org, or your role lacks **Connect AI assistants** |
| `403 Forbidden` on requests | AI features are off for the organization, or the signed-in user lacks **Connect AI assistants** — see [Prerequisites](#prerequisites) |
| Assistant can read but not create/update | Write scopes weren't granted during authorization — remove and re-add the connector, approving write access |

Each assistant guide has its own troubleshooting table for client-specific issues.

## Frequently asked questions

<AccordionGroup>

<Accordion title="Does connecting an AI assistant cost extra?">
Ask your account manager what your plan includes. Inside Sessionboard, connecting needs no separate switch, only AI features turned on for the organization. See [Prerequisites](#prerequisites) for how to check.
</Accordion>

<Accordion title="Does turning on AI features start anything automatically?">
Not for connected assistants. An assistant reads or changes your data only when someone asks it to in a chat. To create or update anything, the person must also have granted write access when they connected it.
</Accordion>

<Accordion title="Can we connect our company's own AI assistant?">
Yes, if it supports a remote MCP server with OAuth. Point it at your region's server URL from the table above. Each person then signs in with their own Sessionboard account and authorizes the organization, and needs **Connect AI assistants** in their role.
</Accordion>

</AccordionGroup>
