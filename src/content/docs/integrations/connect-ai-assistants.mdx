Sessionboard ships a remote **MCP (Model Context Protocol) server** that lets AI assistants securely query and act on your event data. Once connected, you can ask things like *"How many sessions are still pending review?"*, *"Search for keynote sessions,"* or *"Create a new session called 'AI in Events'"* — and the assistant works directly against your organization, scoped by OAuth sign-in.

<Note>
This page covers what you need before connecting and what to expect afterwards. For the technical reference — the full tool list, prompt templates, SbQL, the security model, and example conversations — see the [MCP Server documentation](https://apidocs.sessionboard.com/insights/mcp-server) in our public API docs.
</Note>

## Pick the server URL for your region

Your organization's data lives in one region, and each region has its own MCP server. Use the server that matches where you sign in to Sessionboard:

| Your admin login URL | Region | MCP server URL |
|----|----|----|
| `appv2.sessionboard.com` | United States | `https://mcp.sessionboard.com/mcp` |
| `appv2-eu.sessionboard.com` | Europe | `https://mcp-eu.sessionboard.com/mcp` |
| `appv2-me.sessionboard.com` | Middle East | `https://mcp-me.sessionboard.com/mcp` |

<Warning>
The regions are separate deployments — a connector pointed at the US server cannot see an EU or Middle East organization, and vice versa. If your assistant connects but shows no organizations on the consent screen, you're almost certainly on the wrong regional URL.
</Warning>

## Prerequisites

Before connecting, three things must be true:

1. **AI features are enabled for your organization.** Contact [support@sessionboard.com](mailto:support@sessionboard.com) or your account manager if you're not sure.
2. **Your user has the AI Access permission.** Organization administrators have it by default; other roles need it granted under your org's role settings.
3. **Your assistant supports remote MCP servers with OAuth.** All four assistants above do — plan requirements are noted in each guide.

No API token is required for this flow — the assistant walks you through OAuth sign-in and you choose which organization to grant access to. If you'd rather use a manually generated token (for scripts or non-OAuth clients), see [Generating API tokens](/integrations/api-tokens).

## What you can ask

The MCP server exposes 38 tools covering search, natural-language queries (via SbQL), reporting, and — if you authorize them — write operations. Some starting points:

- *"What events do we have in Sessionboard?"*
- *"How many sessions are still pending review for [event name]?"*
- *"Search Sessionboard for keynote sessions"*
- *"Show me the top 10 speakers by session count"*
- *"Create a new session called 'AI in Events' in [event name]"*
- *"Run our speaker-status report and summarize it"*

The complete list of tools, their parameters, and worked example conversations live in the [MCP Server reference](https://apidocs.sessionboard.com/insights/mcp-server).

<Tip>
Write actions (creating or updating sessions, contacts, metadata, and so on) only work if you granted write scopes during authorization, and assistants ask for confirmation before destructive changes.
</Tip>

## Privacy and PII

Two different rules apply, depending on how the assistant reads your data:

- **Natural-language and SbQL query results are always masked on OAuth connections.** When the assistant answers questions through Sessionboard's query engine (most reporting and "how many / show me" prompts), contact email addresses come back as `j***@a***.com`, phone numbers as `***-***-4567`, and similar masking applies to other personal fields. This is enforced server-side for every OAuth connection and can't be turned off.
- **Direct record reads follow your granted scopes.** When the assistant opens a specific record (for example, pulling up one contact's profile), it receives the fields your authorization allows, unmasked. Only connect assistants you trust, and remember that anything the assistant reads can end up in its conversation history.

If you connect with a manually generated API token instead of OAuth, PII masking on query results is controlled by that token's **Hide PII** setting — it's **off by default**, and we recommend enabling it for AI assistants and third-party integrations. See [Generating API tokens](/integrations/api-tokens#5-hide-pii-recommended-for-ai-and-third-party-integrations).

## Troubleshooting

| Symptom | Likely cause |
|----|----|
| Consent screen shows no organizations | Wrong regional URL, AI features not enabled for your org, or your user lacks the AI Access permission |
| `403 Forbidden` on requests | AI features or MCP access not enabled — see [Prerequisites](#prerequisites) |
| Assistant can read but not create/update | Write scopes weren't granted during authorization — remove and re-add the connector, approving write access |

Each assistant guide has its own troubleshooting table for client-specific issues.
