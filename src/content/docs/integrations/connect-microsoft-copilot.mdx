Microsoft Copilot connects to Sessionboard through **Copilot Studio**: you add the Sessionboard MCP server as a tool on an agent, then publish that agent wherever your team uses Copilot — Microsoft 365 Copilot, Teams, or a web chat. Once connected, the agent can query and (with write scopes) act on your event data.

<Note>
This page covers the Copilot-specific setup. For prerequisites (AI features, the AI Access permission), example prompts, and privacy details, see [Connect AI assistants to Sessionboard](/integrations/connect-ai-assistants). The full tool list lives in the [MCP Server reference](https://apidocs.sessionboard.com/insights/mcp-server).
</Note>

## Pick the server URL for your region

| Your admin login URL | Region | MCP server URL |
|----|----|----|
| `appv2.sessionboard.com` | United States | `https://mcp.sessionboard.com/mcp` |
| `appv2-eu.sessionboard.com` | Europe | `https://mcp-eu.sessionboard.com/mcp` |
| `appv2-me.sessionboard.com` | Middle East | `https://mcp-me.sessionboard.com/mcp` |

## What you need on the Microsoft side

- Access to [Copilot Studio](https://copilotstudio.microsoft.com/) (licensed through Microsoft 365 Copilot or standalone)
- **Generative orchestration** enabled on the agent — Copilot Studio requires it for MCP tools
- Sessionboard's MCP server uses the **streamable HTTP** transport, which is the transport Copilot Studio supports

## Add Sessionboard to a Copilot Studio agent

<Steps>
  <Step title="Create or open an agent">
    Sign in to [Copilot Studio](https://copilotstudio.microsoft.com/), and create a new agent (or open the one you want to extend).
  </Step>
  <Step title="Add the MCP tool">
    Go to the agent's **Tools** page, select **Add a tool → New tool → Model Context Protocol**. The MCP onboarding wizard opens.
  </Step>
  <Step title="Enter the server details">
    - **Server name:** `Sessionboard`
    - **Server description:** `Query and manage event data in Sessionboard — events, sessions, speakers, contacts, sponsors, exhibitors, and reports.` (the agent uses this to decide when to call the server, so keep it descriptive)
    - **Server URL:** the MCP server URL for your region from the table above
  </Step>
  <Step title="Choose OAuth with dynamic discovery">
    Under authentication, select **OAuth 2.0**, then **Dynamic discovery**. Sessionboard's MCP server supports OAuth dynamic client registration with discovery, so Copilot Studio finds the sign-in endpoints and registers itself automatically — no client ID, secret, or endpoint URLs to type in. Select **Create**.
  </Step>
  <Step title="Sign in and add to the agent">
    In the **Add tool** dialog, create a new connection — this launches the Sessionboard OAuth flow. Sign in with your Sessionboard admin credentials, pick your organization on the consent screen, and click **Authorize**. Then select **Add to agent**.
  </Step>
  <Step title="Test, then publish">
    In the agent's **Test/Preview** pane, ask something like *"What events do we have in Sessionboard?"* and check the activity trace shows a Sessionboard tool call. When it works, publish the agent to the channels your team uses (Microsoft 365 Copilot, Teams, or web).
  </Step>
</Steps>

<Tip>
Microsoft's own walkthrough of these screens: [Connect your agent to an existing MCP server](https://learn.microsoft.com/microsoft-copilot-studio/mcp-add-existing-server-to-agent).
</Tip>

## Notes for admins

- Copilot Studio reflects the Sessionboard tool list dynamically — when Sessionboard adds or updates tools, the agent picks the changes up without reconfiguration.
- MCP access in Copilot Studio rides on Power Platform connectors, so Power Platform **data loss prevention (DLP) policies** apply. If the connection is blocked, check your tenant's DLP configuration.
- Each user of the published agent signs in with their own Sessionboard account, so Sessionboard permissions and the AI Access requirement apply per user.

## Troubleshooting

| Symptom | Likely cause |
|----|----|
| Wizard can't reach the server | Wrong regional URL — check the table above |
| Consent screen shows no organizations | AI features not enabled for your org, or your user lacks the AI Access permission — see [Prerequisites](/integrations/connect-ai-assistants#prerequisites) |
| Connection blocked in Copilot Studio | Power Platform DLP policy governing custom MCP connectors |
| Agent never calls the tool | Generative orchestration is off, or the server description is too vague for the orchestrator to match prompts to it |
