Applications can be customized to collect any information you want to store with the person. Examples of use cases are:
- Request to Speak Application
- Awards Application
- Pitch Competition Application

Once submitted, applications can be updated individually or in bulk. You can approve or deny applicants and communicate with them directly from the platform using custom email templates.

## When to use Applications

An application is a form about a **person**: who they are and whether they should take part. A submission form is about a **proposal**: a session, abstract or poster with a title that can be accepted, scheduled and published. Pick the form by what you are collecting.

| You are collecting | Use |
|---|---|
| A proposal for a session, abstract or poster | A [submission form](/sessions/submission-forms) |
| A request to speak, mentor, volunteer, review, join a committee or exhibit, where you decide on the person before any session exists | An **application** |
| A nomination into categories with judges, scoring rubrics and rounds | [Awards](/awards/getting-started) |
| Details from people you have already accepted, such as headshots, bios, agreements or travel | A [portal form](/portals/create-assign-forms) or [task](/portals/assign-tasks) |
| Interest from potential speakers before you open a call, across events | An [interest form](/speaker-crm/speaker-crm-interest-forms) |

The application programs organizers run most often are a request-to-speak form for events without a call for papers, sponsor and exhibitor applications, awards and scholarship intake, volunteer and committee recruitment, and mentor programs. Applicants land in your contacts, so everyone you accept can be added to a session, a portal or a campaign without re-entering their details.

Two limits to plan around: evaluation plans run on sessions and submissions, not applications, so review applications from their status queues; and applications are managed inside Sessionboard, with no integration or API. For the full comparison across every form type, see [Which form should I use?](/concepts/which-form-should-i-use)

## How To Create An Application
1. Navigate to the Applications module and select the "Create Form" button.

   ![How To Create An Application](/images/kb/dd5b3165-image-png-Feb-25-2026-07-22-20-9733-PM.png)

2. Configure your application form by editing the **Welcome Screen**, **Applicant Information**, and **Form Settings** pages. Applicant Information always collects first name, last name and email; add any other contact field with **Add Field**. Form Settings holds the close date, **Match submissions to existing contacts by email**, the **Default status for new submissions**, which admins to notify, and the confirmation email.

![Configure your application form by editing the Welcome Screen, Application Information](/images/kb/5103848f-image-png-Feb-25-2026-07-22-55-9293-PM.png)

Conditional Logic/Question Rules

Use question rules (conditional logic) to create customizable forms that adjust based on the answers that your users provide to various questions. This allows you to use one form to intake multiple different types of application submissions.

![Use question rules (conditional logic) to create customizable forms that adjust based on the answers](/images/kb/606464e2-image-png-Feb-25-2026-07-24-03-0991-PM.png)

Question rules can only be used on the following field types:
- Textbox
- Dropdown
- Number

<Tip>
When using question rules, you want to apply the rule to the conditional question.
</Tip>

Question rules only hide or show questions. To write other field values when the application is saved, use an Assignment [Field Rule](/settings/field-rules).

## Share the application form
When it is time to start accepting applications, email the application link or include it on your website. This link can be found using the instructions below.

Navigate to the Applications module, open the menu on the application form's card and select **Copy Link**; it copies the application form URL to share with your event community. **View Form** opens the form as an applicant sees it, and the same two buttons sit at the top of the form editor.

![Share The Application Form](/images/kb/7c92803e-image-png-Feb-25-2026-07-39-50-7580-PM.png)

Once an applicant completes the form, they will be redirected to the event portal. Applicants can log back into their portal at any time to view or edit their application.

## View application submissions
1. Within the Applications module, click your application form's card, or open its menu and select **View Submissions**.

   ![View Application Submissions](/images/kb/36282d6f-image-png-Feb-25-2026-07-41-42-2602-PM.png)

2. You will have access to a dashboard where you will be able to review all applications received and update their status. The tabs across the top are the status queues: **Accepted**, **Accept Queue**, **Pending**, **Decline Queue** and **Declined**, plus **Drafts** for applications started but not submitted. Click a **Status** cell to move one application; select several rows to **Send Emails** to the applicants from the table. **Options** exports the table as CSV or XLSX. New applications arrive with no status unless the form sets one: in the form editor, **Default status for new submissions** starts every application from that form in the status you choose. Leave it on **No status (default)** to keep applications unassigned until you review them.

![You will have access to a dashboard where you will be able to review all applications received and update](/images/kb/c8aa505c-image-png-Feb-25-2026-07-48-43-7361-PM.png)

## Frequently Asked Questions
1. Do applicants have access to the portal?
   1. Yes, applicants will be directed to the portal once they have completed filling out their application.
2. Can I use an integration or open API with applications?
   1. No — applications are managed inside Sessionboard.
3. Can I create an evaluation plan for applications?
   1. No. Evaluation plans run on sessions and submissions; review applications from the applications dashboard.
