## Export a table

1. Open the module and shape the table first — the export contains the **columns of the view you are looking at**, in that order, with the current filters applied. See [Module table views](/reporting/dashboard-views).
2. Click **Options** in the top-right corner of the module.
3. Choose **Export .CSV** or **Export .XLSX**.

![The Options menu on the Sessions module, with Export .CSV, Export .XLSX and Download files bundle](/images/kb/reporting-options-export.png)

The file is generated in the background and downloads when it is ready.

On the Sessions module, **Download files bundle…** is also here. It opens the **Download Files** wizard: choose which sources to include (form uploads, file requests, headshots and so on) and how to organise them inside the zip, then **Generate download**. The bundle is built in the background and you get an email with a download link when it is ready; large bundles can take several minutes. Looking for headshots specifically? See [How to download headshots](/faq/how-to-download-headshots).

<Note>
File fields in a CSV or Excel export come through as **publicly hosted links** to each file, not as the files themselves. Use the files bundle when you need the files.
</Note>

Exporting is a permission. A role needs **Can export sessions** (or the matching export permission for contacts, speakers, sponsors and exhibitors) under **Event Team → Permissions**; otherwise the export items in the Options menu are disabled.

<Tip>
If you need the same shape again — a column set for the printer, a filter for one committee — save it as a view before you export. Next time the export is two clicks. For anything more than a flat table, such as sessions with their speakers grouped by track, build it once in the [Report Builder](/reporting/report-builder) and download or schedule it from there.
</Tip>

## Dates and times in an export

Every date and time in a downloaded file is written in the **event timezone** from [Event Details](/events/event-details). Exports that aren't scoped to one event — organization-wide Awards exports, for example — use your organization's timezone instead. That is often not the timezone of the person opening the file, and it is not the timezone the on-screen grid uses either, which renders in the reader's own browser.

So every exported value names the zone it belongs to:

| In the file | Means |
| --- | --- |
| `2026-04-01 18:30 PDT` | The zone has an abbreviation, so the abbreviation is used |
| `2026-04-01 18:30 UTC-04:00` | The zone has no standard abbreviation, so the offset is spelled out |
| `2026-04-01 18:30 UTC` | No timezone is set, so the value is UTC |

<Note>
If your export format already includes a timezone token, nothing is added — you won't get two markers on one value. When dates and times are split into separate Date and Time columns, the marker sits on the Time column, since a calendar date on its own has no time of day to be ambiguous about.
</Note>

On-screen report grids are deliberately left unlabelled. The marker is for files that leave Sessionboard and get read somewhere else.
