An abstract is a record in the same **Sessions** list as a session. Whether a submission form collects **Abstracts** or **Sessions**, what arrives is a session record, flagged as an abstract. In the Report Builder you choose which of the two a report covers. See [Collect and review abstracts](/sessions/abstracts) for how abstracts become sessions.

## Pick which one you are reporting on

The Report Builder has no **Type** column. Instead, the **Reporting on** list at the top of the builder has two separate choices, **Sessions** and **Abstracts**, and each report covers one of them.

1. Open **Reports** and start a report in the [Report Builder](/reporting/report-builder).
2. In **Reporting on**, choose **Sessions** (scheduled program sessions) or **Abstracts** (submissions that have not become sessions). Changing this clears the report's columns, so choose it first.
3. Add the columns you want from the **Fields** panel. Both choices offer the same session fields, with the same names as the columns in the **Sessions** grid.
4. Add **Source** to see which submission form each record came through.
5. To compare the two side by side, build one report on each and open them together, or export both and combine them in a spreadsheet.

<Note>
A **Type** field (**Abstract** or **Session**) does exist on events that use Sessions 2.0, but it belongs to the Sessions list and its saved views, not to the Report Builder. In a report, the choice in **Reporting on** does that job.
</Note>

## What converts when an abstract becomes a session

When an admin converts an abstract into a session in place, from then on the record counts as a session, not an abstract. A report on **Abstracts** stops listing it and a report on **Sessions** starts listing it. Records built into a separate session by a different route stay separate rows. See [Collect and review abstracts](/sessions/abstracts).

## Related reports

- **Reviews on the same report.** Add scorecard questions from the **Reviews** group to keep one row per record, with answers summarised. See [Review answers, one row per session](/reporting/report-builder#review-answers-one-row-per-session).
- **Subsessions.** Subsessions are their own rows. Filter **Is Subsession** and add the **Parent session** fields to show the parent next to each. See [Sessions and subsessions on one row](/reporting/report-builder#sessions-and-subsessions-on-one-row).
- **A view instead of a report.** To work in a table, the **Abstracts** list and the Sessions list both accept saved views. See [Dashboard views](/reporting/dashboard-views).
